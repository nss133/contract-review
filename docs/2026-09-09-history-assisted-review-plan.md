# 과거 태깅자료를 활용한 거래성격 분류·조항매칭·판정 개선 기획

- 작성일: 2026-09-09
- 상태: 기획안, 구현 전
- 기준: v1.51.1 작업트리
- work_id: CW-20260825-EF96D7EB
- 사용자 방향: 과거 부서별 분류를 현행 계약유형에 일대일 연결하지 않고, 계약 내용·거래성격·개인정보 관계·부서·태그를 함께 활용하여 자동분류와 검토 효율을 개선한다.

## 1. 현재 동작과 문제

- src/app.js의 renderHistoryTypeMap은 과거 신청·결과의 유형값을 현재 유형 하나에 연결한다. 부서 전용 설정은 아니지만 과거 유형 자체가 조직별 분류라면 부서와 거래성격을 혼동하게 된다.
- applyHistoryReference는 과거 건을 사용자가 선택하면 연결된 유형으로 onTypeChanged를 호출한다. 안내에는 참고라고 쓰지만 실제 현재 유형이 변경되는 동작이다.
- src/legal_opinion_knowledge.js의 matchText는 태그명·별칭의 문자열 일치와 빈도로 후보를 보여준다. 부서·유형 태그는 제외하고, 적재 자료는 현재 분류 점수나 자동판정에 직접 반영하지 않는다.
- 내장 계약 태그 엔진의 검수된 signature 보조매칭과, 사용자가 적재한 과거 태깅자료는 별개의 경로다. 전자의 작동을 후자의 학습효과로 설명하면 안 된다.
- 과거 검색은 수동 사전채움·원계약 참고용으로 설계됐으나 사용자가 기대한 자동 활용의 주 흐름이 되지 못했다.

## 2. 목표 분류체계

다음 축을 분리해 한 계약에 함께 보존한다. 원본 DB 값은 덮어쓰지 않는다.

| 축 | 예시 | 역할 |
|---|---|---|
| 거래성격 | 용역, 임대차, 매매, 비밀유지 | 기본 계약유형·기본 체크셋 |
| 업무·대상 | 정보보안 점검, 사무공간, 장비, 행사 | 세부 체크 후보 |
| 당사 역할 | 발주자, 임차인, 임대인, 수탁자 | 권리·의무의 방향 |
| 개인정보 관계 | 처리위탁, 제3자 제공, 없음, 불명확 | 적용범위 질문과 관련 체크 |
| 기타 적용범위 | 금융업무위탁, 전자금융 외주 등 | 각 적용범위 엔진의 독립 판단 |
| 부서 | 정보보호, 총무 등 | 사례 간 문맥 유사성의 제한적 보조 |
| 원본 분류 | 과거 유형A/B 및 결과 유형 | 출처·시대별 해석이 필요한 참고값 |

동일 정보보호부서가 보안점검 용역과 사무실 임차를 체결하면 각각 용역과 임대차가 되어야 한다. 부서가 같다고 개인정보 처리위탁까지 동일하게 설정하지 않는다. 복합계약은 주유형과 부가 성격을 함께 남긴다.

## 3. 기본 사용 흐름

1. 태거 XLSX를 한 번 적재한다. 한 번의 읽기로 이력과 태그 저장소를 준비하고 두 저장소의 성공·실패를 각각 표시하며 실패분만 재시도한다.
2. 폐쇄망 안에서 과거 건별 거래성격·역할·개인정보 관계 후보를 계산한다. 옛 유형값을 정답으로 쓰지 않고 제목·요청내용·문서역할·태그의 출처를 대조한다.
3. 신규 계약을 입력하면 현재 제목·본문·첨부와 선택적 부서/요청정보를 읽고 관련 과거 사례를 자동 검색한다. 추가 입력 없이도 기존 계약 분석은 가능해야 한다.
4. 현재 문서의 직접 신호에 과거 사례의 보조 신호를 결합해 유형과 관련 체크를 제안한다. 명확한 경우 자동 설정하고 혼동되는 경우에만 핵심 질문을 보여준다.
5. 체크항목별 후보 조항을 재정렬하고 현재 조항에서 필수 요소·주체·조건·금지/허용·예외·당사 역할을 검증한다.
6. 자동완료 허용 항목은 검증을 통과했을 때 이상없음을 기재한다. 나머지는 근거와 추천을 보여주고 사람 판정을 받는다.
7. 사람이 바꾼 유형·조항·판정·실제 조치를 서로 다른 학습 표본으로 축적한다.

## 4. 자동 활용의 구체적 범위

### 유형과 적용범위

- 제목·본문의 거래대상, 지급 구조, 수행 의무, 당사 역할을 우선한다.
- 과거 자료는 거래성격이 유사한 후보의 순위를 조정하고 질문을 줄이는 데 사용한다.
- 부서는 내용이 유사한 후보 간 보조 신호로만 쓰며, 내용 근거가 없는 유형을 새로 만들거나 직접 근거를 뒤집지 못하게 한다. 조직개편·부서명 변경은 기간과 별칭으로 관리한다.
- 과거 개인정보 여부 Y/N은 당시 선언값이다. 복합 질문의 Y를 처리위탁으로 바로 바꾸지 않고, 현재 문언으로 처리위탁/제3자 제공을 구분한다. 빈칸은 없음으로 바꾸지 않는다.
- 규칙이 만든 과거 재분류 후보는 자동생성 표본으로 표시한다. 이를 사람 정답처럼 재학습해 확신을 증폭시키지 않는다.

### 조항매칭

- 과거 쟁점·태그·근거 문장은 검토할 항목과 조항 후보를 찾는 데 활용한다.
- 원문 조항과 체크 ID, 사람 확인까지 연결된 표본은 정답 조항 학습에 사용한다.
- 검토의견서의 문장을 계약서 조항으로 혼동하지 않는다. 수정 제안은 실제 계약 반영 문구와 구분한다.
- 원시후보·정규/엄격 태그, DB 직접값·본문 의미태그, 신청·결과 출처를 유지한다. 같은 의미를 가진 여러 태그의 중복 가점을 제한한다.

### 이상없음

- 자동완료 단위는 개별 체크항목이다. 계약 전체의 과거 이상없음이나 의견 공란을 모든 항목의 정답으로 변환하지 않는다.
- 과거 유사조항과 사람 판정은 현재 항목의 추천과 자동화 후보 발굴에 사용한다.
- 실제 자동 기재에는 현재 계약의 직접 근거, 해당 체크의 필수 요소 충족, 역할·조건 일치, 반대 문언 부재, 자동완료 허용 정책을 요구한다.
- 현재 canAutoPass 및 auto_verdict:false 정책을 우회하지 않는다. 자동화 범위 확대는 항목별 별도 검증 후 적용한다.
- 이상없음의 사유(반영/해당사항 없음), 검토의견, 실제 수정·삭제·유지 조치를 별개로 보존한다.

예: 과거에 사전동의 재위탁 조항이 통과했더라도 현재 문구가 사후통지이면 자동완료하지 않는다. 비밀유지 태그가 같아도 의무주체·기간·예외가 다르면 같은 판정을 옮기지 않는다.

## 5. 화면 개편

- 일반 화면의 DB 유형 수동 연결을 제거한다. 기존 설정은 이관 기록으로 보존하되 현재 유형을 직접 변경하는 경로에서는 비활성화한다.
- 적재 화면은 자료 건수와 활용 가능 범위를 표시한다: 분류 참고 가능, 쟁점 참고 가능, 조항 근거 있음, 사람 판정 있음, 연결 확인 필요.
- 과거 계약검토 찾기는 선택적인 이력 조회 영역으로 접는다. 주 흐름에는 자동 검색된 관련 근거만 표시한다.
- 분석 상단에는 주유형·부가성격·당사 역할·개인정보 관계 및 판단 이유를 간결하게 보여준다.
- 카드에는 현재 근거, 과거 참고, 자동완료 사유를 구분한다. 사례 건수 자체를 정확도나 법적 신뢰도로 표시하지 않는다.
- 검토자는 평소처럼 유형과 판정을 수정한다. 일반 사용자가 DB 전체의 연결표를 먼저 완성할 필요가 없게 한다.

## 6. 데이터 신뢰성 선행 수정

- v1.51.1은 태거의 ROW-2 같은 행 기반 문서 ID도 원천 ID로 취급한다. 이것은 원천 검토번호의 안정성을 보장하지 않는다. 태거 코드 역시 원천 ID 부재 시 ROW-행번호를 발급하므로 파일 간 잘못된 병합을 막아야 한다.
- 원천 시스템 검토번호, 태거 문서 ID, 파일 안의 행 ID를 분리한다. 행 ID는 파일/데이터셋 범위로 제한하고, 파일 간 대응은 검증된 식별자가 없으면 자동 확정하지 않는다.
- 원본+태깅결과와 문서대장은 상호 검증한다. 문서대장 우선만으로 원본의 분할기간·유형B·신청/결과 필드가 완전히 보존된다고 가정하지 않는다.
- 현재 headerIndex는 별칭 우선순위가 아니라 열 순서로 첫 일치를 선택한다. 대표 계약명이 신청·결과 계약명을 가리는 경우를 고쳐야 한다.
- 태거의 실제 헤더 추론에서 제목과 계약검토_계약명, 유형A/B, 계약기간 시작/종료가 올바르게 대응하는지 합성 양성·혼동 표본으로 검증한다. 잘못 분리된 자료는 자동활용 전에 재정규화한다.
- 태깅자료만 적재한 경우에도 확보된 메타데이터·태그·근거는 활용하되, 누락된 원문·역할·신청/결과를 추정하여 채우지 않는다.
- 적재/정규화/분류정책/태거 버전과 사용 근거 ID를 기록하고 업데이트 시 파생 인덱스를 재생성한다. 사용자가 확정한 판정은 보존한다.

## 7. 구현 순서와 검증

1. P0: ID 충돌·헤더 의미·원본/문서대장 보존을 수정하고 일대일 유형 강제변경을 해제한다.
2. P1: 1회 통합적재, 다축 사례 인덱스, 자동 과거 검색, 내용 중심 분류 보조와 설명 UI를 구현한다.
3. P2: 출처와 역할을 보존한 체크별 조항 재정렬, 사람 조항 교정 수집을 구현한다.
4. P3: 사람 판정과 현재 문언을 검증할 수 있는 항목부터 자동 이상없음 후보를 평가·승격한다.

검증 세트는 정보보호부서의 용역/임대차/매매, 같은 거래의 부서 변경, 개인정보 위탁 Y/N/미기재/충돌, 사전동의/사후통지, 원문 없는 과거 이상없음, 서로 다른 파일의 ROW-2 충돌을 포함한다.

내용만/내용+과거자료/내용+과거자료+부서의 세 조건을 비교한다. 부서 추가로 문언이 명확한 유형이 뒤집히는 사례는 허용하지 않는다. 신규 부서와 조직개편 사례를 별도로 평가한다.

유형 정밀도와 보류율, 적용범위 오탐·누락, 조항 Top-1/Top-3, 잘못된 자동 이상없음 비율과 자동완료율, 사람 교정률·클릭 수를 따로 측정한다. 같은 계약군·개정본이 학습과 평가에 섞이지 않도록 시간·계약군으로 분리한다. 현재 대상 건의 사후 검토결과는 입력 특성에서 제외한다.

초기 고위험 회귀표본에서 잘못된 자동 이상없음 0건을 필수 조건으로 하되 이를 운영 전체의 무오류 보장으로 해석하지 않는다. 자동화 후보에 대한 검증 표본이 부족하면 추천만 제공한다. 실제 평가와 학습 자료는 폐쇄망 내부에 유지한다.

## 8. 이번 기획의 범위

사용자 진행 승인 후 1.52.0에서 데이터 식별·헤더 우선순위 수정, 수동 유형 강제변경 해제,
태그/이력 1회 통합적재, 공통어 기반 자동 과거 검색, 직접 후보에 한정된 유형·조항 보강을 1차 구현했다.
공통어 복수와 기존 본건 최소점수/핵심근거 게이트를 요구한다. 과거 보너스가 있는 후보는
본건 문장요건 또는 회사관점 확인 없이는 자동 이상없음으로 처리하지 않는다.
같은 파일의 행 위치와 계약명이 일치한 경우에만 원본 신청·결과 필드를 태그 문서에 연결한다.

후속 1.53.0: 독립 규제 해당성 입력·문장 출처·서술 결과·사실보정·백업을 구현하고,
해지권·해지절차·종료후처리·비밀유지존속의 4개 표시 묶음과 공통 해지권 질문의 절차 중복을 정리했다.
규제 결과는 정의요건 중심의 후보/추가확인으로 한정하며 법적 확정·신고의무 확정을 하지 않는다.
미완료: 역할·규제축을 포함한 전체 사례 인덱스, 사람 조항 교정의 학습 반영, 실자료 평가 및 자동완료 범위 확대.
현재의 어휘 기반 보조만으로 매핑 정확도 향상이나 자동완료율 상승이 입증되었다고 보지 않는다.
