# v1.88 구조·목록·참조 시험 마이그레이션

대상: context_expansion, obligation_lists, nested_obligation_lists, condition_expansion, complex_references, range_references, table_obligations 시험 7개.

## 변경한 기대와 이유

- 비활성 항목은 직접 판정 대상이 아니므로 eligible=false 및 disabled_check를 검증한다. 같은 fixture의 Q/D 의미 키 비교는 계속 실행한다.
- SOL-05는 일반 수탁자 교육·기록 운영에서 관련 모집 업무 교육·점검 약정으로 질문이 바뀌었다. 모집 업무 연결이 없는 기존 일반관리 fixture는 새 질문의 양성으로 사용하지 않는다. 원래 문구의 파서 동등성 검증은 보존한다.
- 이상없음 이력 또는 정정 이력만으로 현행 판정 결과를 바꾸지 않는다. 본건에 인력관리 약정이 있으면 직접 판정하고, 비밀유지 제목이 인력·기록·기간만 참조하면 보호 범위 및 사용·공개 제한의 약정을 추정하지 않는다.
- 동일한 실질 요건인 인력 변경 시 / 인력 변경되는 경우에만은 약정 존재를 인정한다. 반면 가능한 경우에만, 상대방이 동의하는 경우에만, 단순 노력·재량으로 필수 의무를 약화시키는 문구는 음성 기대를 유지한다.
- 번호 중복·빠짐·기호 혼합·구역 변경 자체는 직접 읽을 수 있는 약정의 부재가 아니다. 본건 문장의 필수 내용이 남으면 직접 판정하고, Q/D의 엄격한 목록 경로·범위 동일성 검증은 종전대로 유지한다.
- ITSEC-12 인력관리 방안의 존재를 묻는 질문은 갑/을 호칭·주체 변경만으로 전부 보류하지 않는다. 반면 PRIV-03처럼 수탁자 보호의무가 전제인 질문에서 위탁자만 부담하도록 명시 역전된 경우는 음성으로 유지한다. 엄격 비교의 별칭 변경 검증도 보존한다.
- 주체·대상·의무의 정상 표에서 의무 칸의 기술적·관리적 보호조치 명시는 존재형 질문의 약정이다. 종결 동사 생략만으로 보류하지 않되 대상과 셀 연결이 불명확한 경우는 구분한다.
- 현재 판정 근거는 약정 본문과 정확한 원문을 검증한다. 종전 S 결과에서 모든 목록 도입문·표 머리글을 개별 근거 행으로 요구하던 조건은 제거했다. Q/D의 상위 도입문·셀 구조 검증은 그대로 남아 있다.
- 등록 표준의 인용 후보가 반복되더라도 주체 자체가 요건이 아닌 ITSEC-12의 관리방안 원문이 실제로 있으면 표준 비교를 할 수 있다. 정상 표준 존재 시 L의 충족, 표준 부재 시 L의 미충족, 그때도 본건 직접 판정 S는 충족인 경우를 각각 검증한다. 등록 표준의 과거 결론을 복사하거나 없는 표준 출처를 만들어내는 시험이 아니다.

## 유지한 실제 음성

- 필수 신원확인 또는 인수인계 약정의 부재·명시 면제.
- 특정 호·목·세목 및 범위의 적용 배제. 별첨의 동일 번호를 본문의 번호로 임의 연결하지 않음.
- 신용정보 재위탁 금지를 위탁자의 일반 동의로 대체하는 예외.
- 보호조치 등 본건 관련 의무의 명시 배제와 모든 의무의 적용 배제.
- 셀 사이 연결을 확인할 수 없는 표의 구조, 문장과 머리글의 명시 주체 충돌, 오래된 원문 좌표. 구조 없는 완전한 문장은 별도로 양성 검증한다.
- 모든 Q/D의 누락·중복·범위·가지번호·참조 순환·외부 법령 참조·캐시 단위 검증. P의 엄격한 과거 근거 재사용 단위 검증도 변경하지 않았다.

시험을 skip/todo 처리하거나 실행 결과로 기대값을 계산하지 않았다. 결과값을 확인해 그대로 정답으로 채우는 방식도 사용하지 않았다. 실제 엔진 결함은 해당 음성을 유지한 채 공통 판정 엔진 담당에게 전달한다.

## 실제 브라우저 lifecycle 시험 이관

build/test_auto_lifecycle.mjs의 일반적인 책임을 지지 않는다는 문구를 곧바로 실패시키던 기대를 변경했다. 일반 면책·책임 귀속 문구는 약정 존재 양성으로 검증하고, 회사=갑·상대방=을을 실제 본문에서 식별한 후 상대방의 고의·중과실 손해까지 책임을 배제하는 구체적 위험은 B5 음성으로 검증한다. 입력 편집 직후 이전 자동판정 회수, 재분석, 새로고침, 수기 의견 보존, 사용자가 중지한 설정의 지속·재개, 표준서식 등록·재실행 검증은 유지했다.

브라우저는 새로운 격리 컨텍스트를 생성하고 그 안에서만 실행하며 종료 시 해당 컨텍스트만 폐기한다. 기존 탭과 사용자 localStorage·IndexedDB를 초기화하지 않는다. 이 파일은 정적 구문 검사까지 수행하고 실제 최종 HTML 실행은 배포본 준비 후 별도로 수행한다.
