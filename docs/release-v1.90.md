# v1.90.0 — 대량 태깅자료 분석 시 브라우저 멈춤 수정

## 업데이트

1. 폐쇄망에서 지금까지 사용하던 계약서검토 실행기를 그대로 연다.
2. 버전 설치·업데이트에서 contract-review-v1.90.0.crupdate를 선택한다.
3. 화면 버전 v1.90.0을 확인하고 기존 계약을 다시 분석한다.

실행기 이름·위치를 바꾸거나 새 실행기로 갈아탈 필요가 없다. 브라우저 저장자료를 삭제하지 않는다. 태깅자료·검토이력·표준서식의 재반입이나 재승인도 요구하지 않는다. 자료 백업은 기존 절차대로 폐쇄망 내부에 보관한다.

## 달라진 처리

v1.89에서 마지막 연결 안내 중 화면이 응답하지 않는 현상이 다시 보고되었다. 다양한 과거 근거가 많으면 전체 구절 검색 준비와 질문별 재비교가 화면 처리까지 막는 경로가 확인되어 다음과 같이 변경한다.

- 과거 자료는 관련 체크·주제 후보를 먼저 고르고 필요한 구절만 생성·검색한다. 전체 DB 구절을 매 질문마다 다시 비교하지 않는다.
- 과거 자료 준비·조항 매핑은 브라우저 안의 별도 작업 스레드에서 실행한다. 외부 서버나 LLM을 사용하지 않으며 작업 코드는 HTML에 내장한다.
- 진행 안내는 실제 작업 단계와 연결한다. 취소가 가능한 계산 단계에서는 분석 취소 버튼을 제공한다. 취소된 중간 결과로 자동판정을 저장하지 않는다.
- 자동판정은 현재 약정의 기존 검사를 유지한다. 별도 작업 스레드가 돌려준 과거 참고만으로 이상없음을 발행하지 않는다.
- 조항 연결 선택목록은 열 때 전체 항목을 준비한다. 별첨 완료 영역의 근거 원문도 최대 하나만 표시한다. 내부 출처·좌표·수기 메모는 유지한다.

체크리스트 정책·자동판정 범위를 줄이거나 태깅자료를 제거한 수정이 아니다. 본문·자료 변경 시 이전 결과를 적용하지 않고, 기존 사용자 판정은 보존한다.

## 취소·오류 안내

분석 취소는 계산 중에 사용할 수 있다. 판정 반영을 시작한 뒤에는 취소 버튼이 사라지고 화면 정리를 마친다. 본문·참고자료가 도중에 바뀌었다는 안내가 나오면 현재 내용으로 다시 분석한다.

브라우저가 내장 작업 스레드를 시작하지 못하면 오류를 표시하고 분석 버튼을 복구한다. 이를 숨기고 화면에서 같은 무거운 계산을 다시 실행하지 않는다. 오류가 지속되면 해당 안내 문구를 확인한다. 저장자료 삭제나 임의의 보안정책 완화는 해결 절차로 권하지 않는다.

저장·표시 오류와 계산 취소는 구별한다. 오류 안내가 남아 있으면 검토 완료로 보지 않는다. 사용자 자료나 계약 원문을 외부로 반출할 필요는 없다.

## 검증 범위

검증 완료 여부·측정값·제한은 v1.90-validation.md와 v1.90-performance-acceptance.json을 따른다. 이전 멈춤을 재현한 서로 다른 합성 근거 26,000행 조건과 실제 분석 버튼을 기준으로 화면 응답·취소·기존 결과 보존을 검사한다. 단일 총 소요시간만으로 모든 환경의 멈춤이 해소됐다고 보지 않는다.

이 ZIP에는 실제 사용자 계약·코퍼스·태깅 DB·이력팩을 넣지 않는다. 실제 폐쇄망 장비 및 모든 실계약에 대한 성능 보장은 아니다.
