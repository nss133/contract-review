# v1.58.2 — 실무 체크 제외 및 평가셋 준비

## 체크항목

사용자의 운영 기준에 따라 SP-DEL-08-2(이행·하자보증보험 확인), RISK-02(구상·비용전가 확보)를 활성 체크에서 제외했습니다. 기존 판정 저장소를 삭제하지 않으며, 재분석 이후 해당 두 항목은 검토·완료 집계에서 제외됩니다. 일반 손해배상·하자보수 검토는 유지합니다. 일반 배상조항이 모든 제재·제3자 비용을 법적으로 보장한다는 결론을 자동 부여하는 변경은 아닙니다.

## 현재 평가셋 상태

- 개발 저장소의 YAML 회귀 사례 51건: 유형 분류·체크 노출·매핑 등 코드 변경 회귀 확인용입니다. 실제 폐쇄망 데이터에 대한 정확도 입증 자료는 아닙니다.
- 앱의 내부 평가 기능: 현재 계약 스냅샷 고정, 예측과 분리된 정답 양식, 독립 검수·다계약 취합·개발/시험/반례 분할·매핑 및 잘못된 이상없음 측정 기능이 있습니다.
- 폐쇄망에서 실제 생성한 평가셋 수와 검수 상태는 여기에서 조회할 수 없습니다. 이력 적재만으로 검증된 정답셋이 자동 생성되지는 않습니다.

평가셋은 시험할 사례의 묶음이고, 골드셋은 신뢰할 수 있게 검수한 정답을 갖춘 사례의 묶음입니다. 기존 의견은 정답 후보이자 검수 참고자료로 활용하되 자동으로 정답 확정하지 않습니다.

## 자료를 꺼내는 방법 — 폐쇄망 내부 저장

1. 적재했던 PC·브라우저·기존 영구 실행기를 사용합니다. 브라우저 저장소를 초기화하지 않습니다.
2. 지식 데이터 화면의 ‘계약검토 이력 DB’에서 ‘이력팩 내부 백업’을 선택합니다.
3. 생성되는 contract-review-history_날짜_건수.crhistory 파일을 폐쇄망 내부 승인 폴더에 보관합니다.
4. 법률검토 지식팩도 별도로 적재했다면 지식팩 백업을 별도로 보관합니다. 현재 앱에서 검토한 계약은 리포트 → 팀·지식 관리 → 검토 아카이브 저장으로 보존할 수 있습니다.

이력팩은 앱에 적재·정규화된 이력의 백업입니다. 원본 XLSX의 모든 데이터나 첨부 HWP/PDF 자체의 백업을 보장하지 않습니다. 첨부 칼럼이 파일명·링크라면 실제 계약서·별첨 파일을 내부 문서시스템에서 별도로 확보해야 합니다. 외부 반출이 선행조건이 아니며 이 파일을 외부 채팅에 업로드하지 않습니다.

## 권장 구축 순서

1. 이력팩을 내부 백업하고 원문·별첨·검토의견·문서 버전의 확보 여부를 목록화합니다.
2. 이력에서 계약별 평가 후보를 만들고 부서, 사용 유형, 쟁점, 결과, 개인정보 관련 태그로 표본을 고릅니다. 무의견을 이상없음으로 해석하지 않습니다.
3. 검토 전 계약서에는 당시 지적사항을, 수정 후 계약서에는 수정 후 결과를 연결합니다. 원문 버전이 불명확하면 보류합니다.
4. 사람이 쟁점별 적용 여부, 문제 유무, 직접 근거 조항·문장을 검수합니다. 원문·별첨 누락이나 근거 부족은 판단불가로 남깁니다.
5. 원계약·갱신·동일 서식은 같은 계열로 묶고 개발용과 시험용을 분리합니다. 시험 계약과 그 파생 이력은 검색·태그 학습에도 들어가지 않게 제외합니다.
6. 매핑 정확도와 문제 있는데 이상없음으로 처리한 비율을 별도로 측정하고, 검수·승인된 범위에만 자동판정을 적용합니다.

현재 이력팩을 평가 후보로 일괄 변환하는 연결 기능은 별도 구현이 필요합니다. 우선 내부에서 자료 확보 현황을 확인한 뒤, 이력팩 읽기 → 후보 목록 → 원본 연결 → 검수 양식 생성의 내부 전용 작업 흐름으로 추가하는 것이 적절합니다.
