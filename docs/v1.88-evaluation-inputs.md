# v1.88 독립 수용시험과 평가자료의 실제 범위

작성일: 2026-09-18. 승인된 자동판정 기준 재정의 실행계획 제10절에 따른 개발용 평가자료임. 폐쇄망 실계약 자동판정률·오판율을 측정한 보고서가 아님.

## 1. 먼저 확인한 자료상의 한계

기존 엔진이 내놓은 결과를 정답으로 복제하지 않고 승인계획의 약정 확인 기준으로 양성·음성 기대값을 작성함. 사례 파일은 build/audit_v188_acceptance.cjs, 실행 시험은 tests/v188_acceptance.test.js임. 정책상 폐기한 ‘정해진 완성 문장만 통과’ 시험과 별도로 관리함.

합성 61개는 양성 30개와 음성 31개임.

- 자료실의 등록 표준만 존재하고 본건에 적용·동등 문구가 없으면 자동 충족으로 만들지 않음.
- 양성은 현재 문서에 실제 존재하는 근거 인용을 반환하고 이상없음 티켓으로 연결되어야 함. 티켓 재사용은 불가함.
- 자동 근거가 있어도 최신 수기 판정을 덮어쓰지 않음.

## 3. 제공된 보안관리약정 3종

일반·GA·재위탁 추출 원문은 samples/internal-standards/extracted의 기존 로컬 파일에서 읽음. 시험에 원문을 하드코딩하거나 ZIP에 복사하지 않음. 파일별 원문을 통째로 넣어 작성 안내·다른 조항의 예외가 존재하는 실제 상태에서도 판단하도록 함.

계획에서 확인된 커버 13개를 각 표준에 대해 직접 판정·등록 연결·표준 판정으로 검사함.

- CORE-10, CORE-14, PRIV-03, PRIV-06, PRIV-07, CNS-DAMAGE, PRIV-13, PRIV-19, PRIV-20, ALL-PII-03, CMN-19, ITSEC-04, ITSEC-13.
- 본문 제1조와 보안약정 제1조가 다시 시작하는 별첨 상태의 CORE-10도 별도로 검사함.
- 각 표준에 점검·시정 거절 또는 목적 외 자유이용 특약을 붙인 6개 후속 반례도 검사함. 직접 판정·등록 표준 적용·반대특약이 포함된 표준의 등록 모두 차단되어야 함.

기준표 확정에 따라 개인정보 손해배상 PRIV-08은 CNS-DAMAGE로 통합되었음. 이에 해당 커버 시험의 활성 ID도 CNS-DAMAGE로 승계함. 표준의 손해배상 약정이 인정되어야 한다는 양성 기대값은 그대로 유지함. 아래 v1.87 기준선은 ID 변경 전 PRIV-08을 포함한 최초 실행값으로 보존함.

해당 표준에 직접 포함되지 않은 12개는 잘못된 충족을 차단함.

- ITCL-01, ITCL-02, ITCL-05, ITSEC-02, ITSEC-06, ITSEC-07, ITSEC-08, ITSEC-09, ITSEC-10, ITSEC-12, ITSEC-14, ITSEC-15.

이 시험은 계약상 보호·협조 약정 범위임. 보안교육·점검을 실제로 실시했거나 모든 전자금융 규정을 준수했다고 평가하지 않음. ITSEC-05의 전용회선 대체수단과 ITSEC-11의 복수 통제 범위는 이 13개 일괄 양성에 넣지 않았으며 별도 질문 정의·반례로 검증해야 함.

로컬 표준 파일이 없는 일반 개발 환경에서는 해당 원문 시험을 명시적으로 건너뛸 수 있음. 배포 전에는 CR_REQUIRED_PRIVATE=1로 입력 3종 존재를 강제하고 시험 누락을 숨기지 않음. 전체 존재형 질문의 양성·음성·표현 변형 검사는 전수 기준표에 대응한 별도 시험과 합쳐 확인해야 하며, 이 파일만으로 모든 206개를 검증했다고 주장하지 않음.

## 4. v1.87 기준선 — 개발 전 고정 집계

1.87.0 / standard-auto-v12를 대상으로 최초 실행한 결과임. 위 합성 분모는 삭제·통합 여부와 관계없이 고정하여 이후 인식 개선을 비교함.

| 측정 | 결과 |
|---|---:|
| 합성 양성 충족 | 4 / 30 |
| 합성 음성의 잘못된 통과 | 0 / 31 |
| 독립 Node 수용시험 | 75 통과 / 144 전체, 69 실패 |
| 제목뿐인 관할의 표준 등록 안전시험 | 실패 — 기존 등록 경로 오통과 재현 |
| 보안약정 직접 판정 커버 | 0 / 39 |

합성 직접 경로 음성 0건이라는 값은 표준 경로까지 안전하다는 뜻이 아님. 등록 오통과를 별도 경로 시험으로 반드시 함께 확인함. 보안약정 커버 시험은 직접 판정에서 우선 실패했으므로 당시 같은 테스트 내부의 뒤 단계인 등록·적용까지 모두 통과했다고 해석하지 않음.

최종 개선 결과는 개발 완료 후 별도 실행 기록에 작성함. 위 기준선은 이후 엔진에 맞춰 소급 수정하지 않음. 원문 코퍼스 자동판정률은 미측정으로 유지함.

기준선 측정 뒤 실제 표준의 반대특약 6개를 추가하였으므로 현재 Node 수용시험은 150개임. 최초 144개 기준선과 확장된 최종 집계를 구분함.

2026-09-18 개발 중 재실행에서 CR_REQUIRED_PRIVATE=1 기준 150개 모두 통과했으며 skip은 0개임. 합성 양성 30/30, 합성 음성 오통과 0/31, 실제 표준 3종의 약정 커버·반대특약 경로를 포함한 결과임. 이는 이 독립 시험의 현재 결과이며 기존 회귀 전체·최종 빌드 화면 검증 완료를 대신하지 않음.

## 5. 실제 파일과 화면 수용시험

build/test_v188_acceptance.mjs는 새 독립 브라우저 컨텍스트에서만 실행함. 현재 사용자 저장소를 지우지 않으며 종료 시 시험 컨텍스트를 폐기함. 합성 HWP 5·HWPX·DOCX·텍스트 PDF 바이트를 생성하여 실제 파일 추출기와 입력 화면을 통과시킴. 텍스트 추출 함수를 가짜 결과로 바꾸지 않음.

검사 흐름은 파일 입력 → 실제 추출 → 관할·VAT·대금·기간·해지·손해배상 자동판정 → 기존 삼단 화면 ②열 → 재표시·실제 재분석을 통한 저장 판정 재검증 → 나머지 합성 수기항목 완료 → 검토 마치기임. 저장값 읽기만을 단독 호출하지 않고 앱과 동일하게 저장값 복원 뒤 본건 자동근거를 재평가하는 runAnalysis 경로를 실행함. 나머지 항목은 시험자가 직접 완료한 것으로 처리하므로 ‘전 항목 자동판정’ 시험이라고 부르지 않음.

별첨 번호 재시작의 오탐, 숨은 미결, 자동 완료의 재등장, 최신 수기 판정 덮어쓰기, 외부 HTTP 요청도 확인함. 처리시간은 파일별 종단 소요시간을 기록하되 원시 실행 1회의 결과를 P50/P95 통계로 부르지 않음.

이는 4형식 파이프라인의 합성 파일 검증임. 스캔·손상·암호 파일, 복합 표·레이아웃 등은 기존 추출·완결성 회귀시험과 함께 검사하고 실제 폐쇄망 전체 파일의 무오류를 주장하지 않음.

개발 중 HTML(표시 버전 1.87.0)에서 4형식 모두 자동판정 6건·②열·재분석·검토 마치기·최신 수기 보호가 통과하고 외부 요청은 0건이었음. 파일별 소요시간은 1.92~2.06초였으며 해당 합성 문서에서 추가 수기 완료 항목은 0개였음. 최종 배포 빌드 결과는 별도로 재확인해야 하며, 하네스는 HTML 표시 버전과 VERSION 파일(또는 CR_EXPECTED_VERSION)의 일치도 검사함.

## 6. 실행과 결과 취급

저장소 루트에서 실행함.

    node build/audit_v188_acceptance.cjs --require-private
    node build/audit_v188_acceptance.cjs --assert --require-private
    CR_REQUIRED_PRIVATE=1 node --test tests/v188_acceptance.test.js
    CR_TEST_ENDPOINT=http://127.0.0.1:9359 node build/test_v188_acceptance.mjs

첫 명령은 합성 결과와 원문 없는 코퍼스 구조 통계를 출력함. 두 번째의 합격 판정은 합성 사례에 한정하므로 전체 Node·브라우저 시험을 대체하지 않음. 네 번째는 최종 HTML을 빌드한 뒤 별도 테스트용 디버깅 브라우저를 준비하여 실행함.

로컬 경로가 다른 환경은 CR_PRIVATE_CORPUS와 CR_PRIVATE_STANDARDS_DIR로 지정함. 통계는 로컬 표준 출력으로만 내보내고 원문·작성자·계약명·코멘트 본문을 보고서에 넣지 않음. 실제 자료를 사용할 때 원문계열별 평가와 태그·이력 보조 유무 비교가 가능한지 먼저 확인하며 집계 숫자를 재실행 결과로 대체하지 않음.

## 7. 이전 배포와의 격리 실행 성능 비교

build/benchmark_v188_runtime.mjs는 dist/contract-review-v1.87.0.crupdate의 해시를 검증한 HTML과 새로 빌드한 dist/contract-review.html을 비교함. 각 버전에 별도 Target.createBrowserContext를 생성하고 기존 사용자 저장소를 읽거나 지우지 않음. 이전 HTML은 mkdtemp로 만든 전용 임시 디렉터리에 복원하며 종료 시 그 파일과 빈 디렉터리만 제거함. 두 페이지의 외부 HTTP/WebSocket 요청은 차단하고, 시도나 실행 오류가 있으면 측정 실패로 처리함.

기본 입력은 직접 작성한 합성 계약 14조항, 태깅 문서 300개(법률검토 150·계약검토 150), 태그 정의 14개, 합성 코퍼스 계약 100건·수기 판정 400개임. 코퍼스는 원문 없는 누적 의견 형태로 구성하며 실제 사용자의 코퍼스나 표준약정 원문은 읽지 않음. 같은 JSON 바이트를 양쪽 페이지에 주입하고 입력 지문·바이트 수·적재 건수를 함께 검증함. 유형은 양쪽 모두 outsourcing을 선택하고 등록 표준은 0개, 별도 원문 평가자료 자동저장은 중지 상태로 맞춤.

| 측정 | 범위 | 표기 |
|---|---|---|
| 최초 분석 | 새 컨텍스트에서 조문 분할·입력 갱신·유형 선택·실제 runAnalysis·동기 레이아웃 | 버전별 1회 ms. P50/P95라고 부르지 않음 |
| 반복 재분석 | 동일 입력·저장 판정에서 실제 runAnalysis·동기 레이아웃 | 워밍업 2회 후 기본 12회, P50/P95와 원시 측정값 |
| 반복 화면 렌더 | 실제 renderClauses + renderReport·동기 레이아웃 | 워밍업 2회 후 기본 12회, P50/P95와 원시 측정값 |

반복 횟수는 최소 10회이며 분위수는 nearest-rank 방식임. 반복 구간은 버전 실행 순서를 번갈아 배치하고 두 렌더러를 동시에 측정하지 않음. 두 버전 모두 동작 줄이기를 적용하며 파일 변환·자료 적재·브라우저 시작·비동기 평가자료 저장·GPU 페인트 완료 시간은 측정에서 제외함. 따라서 파일 입력부터 모든 후속 저장까지의 종단 시간과 구별해야 함.

실행은 최종 HTML 빌드 후 별도 테스트 Chrome을 준비하여 수행함.

    CR_TEST_ENDPOINT=http://127.0.0.1:9359 node build/benchmark_v188_runtime.mjs

규모는 CR_BENCH_TAG_DOCUMENTS(기본300), CR_BENCH_CORPUS_CONTRACTS(기본100), CR_BENCH_REPETITIONS(기본12, 최소10)로 조정함. 바꾼 규모는 결과의 scale에 기록되며 서로 다른 입력 지문의 수치를 같은 조건의 비교로 섞지 않음. 진행 상황은 stderr, 최종 집계는 stdout JSON으로 출력함.

이전 페이지는 앱 1.87.0·standard-auto-v12, 현재 페이지는 VERSION 및 현재 소스의 자동판정·공통인식 엔진 버전과 각각 대조함. 전체 기준표 행 수·활성 질문 수·선택 유형의 실제 분석 질문 수·자동 완료 수 차이도 출력함. 질문 통합과 자동 완료 확대 때문에 두 버전의 화면 작업량 자체가 다르므로 순수 엔진 단위 성능 개선률로 환산하지 않음. 실제 원문이나 폐쇄망 장비를 사용한 결과가 아니며, 수치 변동·성능 저하도 그대로 기록하고 개선률을 약속하지 않음.

최종 실행값은 v1.88-validation.md와 v1.88-runtime-benchmark.json에 기록함. CR_BENCH_PROFILE_INITIAL=1을 추가하면 별도 진단 실행에서 초기 색인·검색·자동판정 함수의 호출 수와 포함 시간을 측정함. 이 옵션의 진단 수치는 비계측 기본 실행의 P50/P95와 섞지 않으며, 중첩 호출의 포함 시간을 합산하지 않음. 초기 중복 색인 진단 후 매핑·자동판정이 같은 자료 버전의 색인을 공유하도록 수정했고, 해당 캐시 재사용을 회귀시험으로 고정함.

인용 좌표는 각 호출의 document_index·문서명·start/end로 현재 입력을 다시 잘라 정확히 같은 원문이 나오는지 검사하여 46/46 통과함. 그중 10회는 명시 편입한 표준 원문 인용으로 본문 직접 인용과 구분함. 힌트의 본건 조항 인덱스·본문 일치 16/16, 보강된 매핑 대상 조항 일치 5/5도 통과함. 이 숫자는 7개 설정 및 직접/표준 경로의 검증 호출 수이며 독립 계약 건수가 아님.

재실행 명령은 `node build/audit_v188_sources.cjs`임. 정상 전용 prepare/resolve/evaluate/index/retrieve/run API만 사용하고 내부 캐시를 조작하지 않음. 원문 표준 3종 검증은 앞의 독립 수용시험과 분리되어 있으며, 이 작은 합성 비교로 실제 폐쇄망의 매핑 정확도나 자동판정률 개선 폭을 추정하지 않음.
