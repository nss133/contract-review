# 코퍼스·태깅 기반 자동판정 개선 개발계획

작성일: 2026-09-15
상태: 계획 수립. 이 문서 작성으로 앱 구현·승인 설정은 변경하지 않음.
기준: v1.64 코드 및 사용자가 제공한 29건 코퍼스에 대한 확인 결과.

## 1. 쟁점·진행경과

- 목표는 체크리스트 매핑 정확도 향상과 신뢰 가능한 자동판정 범위 확대임. 이번 개발은 근거가 있는데도 발생하는 보류의 해소와 평가 기능 사용성 개선에 집중함.
- 제공 코퍼스에는 29건, 121개 체크항목, 431개 판정이 집계되어 있음. 이상없음 355개는 과거 결과 분포이며 자동판정률이 아님. 계약별 요약은 8건이고 원문·항목별 근거 연결은 완전하게 보존되어 있지 않음.
- 사용자가 실제 내용을 확인하여 확정한 결과라는 점을 반영함. 다만 개별 기록의 사람·자동 출처, 내용 충족·해당없음·위험 수용은 구분하여 재사용함.
- 현행 코퍼스는 주로 통계·추천에 쓰이며 평가 준비와의 직접 연결이 부족함. 동일 계약 재적재 시 후속 판정이 무시될 수 있고, 문서 전체의 예외·정의문이 승인형 자동판정 후보를 일괄 차단하는 조건이 있음.
- v1.64의 복잡한 평가 절차와 사용자가 보고한 지연을 개선 대상으로 포함함. 지연 원인은 별도 측정 전까지 단정하지 않음.

## 2. 검토의견

| 구분 | 개발 방침 | 유지할 경계 |
|---|---|---|
| 누적자료 | 기존 코퍼스와 계약·법률검토 태깅을 연결함 | 집계자료를 개별 계약의 정답으로 추정 복원하지 않음 |
| 판단 태깅 | 확정 결과·작성 의견·근거를 자동 구조화함 | 생성 태그와 사용자 확정 사실을 구분함 |
| 매핑 | 주제·역할·업무·근거 표현을 활용함 | 이상없음 확정을 매핑 정확성 확인으로 간주하지 않음 |
| 자동판정 | 현재 계약의 충족 조건을 확인하여 보류를 해소함 | 태그 유사도나 과거 통과 횟수만으로 통과시키지 않음 |
| 평가·성능 | 기본 자동 준비·단일 실행·증분 계산으로 단순화함 | 시험 격리와 오류 추적은 내부적으로 유지함 |

## 3. 대응방안 및 완료 기준

- 즉시 조치: 기준 성능을 측정하고 데이터 갱신·출처 보존을 먼저 개선한 뒤, 관련 없는 문장에 의한 보류를 제거함.
- 종결 전 확인: 태깅 유무·코퍼스 연결 유무를 같은 시험사례에서 비교하고 잘못된 자동통과, 매핑 누락, 검토 지연을 확인함.
- 사후 관리: 사람이 수정한 결과를 최신 이력으로 반영하고 오류가 발생한 규칙 범위를 중지·재검증할 수 있게 함.
- 완료는 코드·로컬 회귀시험·배포 묶음 완성과 폐쇄망 실데이터 검증을 구분함. 실데이터 검증 전에는 자동판정 정확도나 개선율 달성을 선언하지 않음.

## 별첨 1. 단계별 구현 범위

### 1단계 — 누적자료 보존·연결 및 기준 측정

- 기존 저장자료를 보존하고 스키마 버전·마이그레이션·복원 경로를 마련함.
- 계약 식별자와 문서 버전을 구분하여 동일 계약 후속 판정이 누락되지 않게 함. 재적재 중복 방지와 수정 반영을 동시에 보장함.
- 신규 기록은 계약·문서 버전·체크항목 단위로 판정, 사유, 근거 위치, 작성자, 판정 출처, 수정 이력을 저장함. 집계는 해당 기록에서 계산함.
- 구 집계자료는 별도 보존하고 신규·복원된 사건기록과 중복 가산하지 않음. 중복 여부가 불명확하면 분리 표시함.
- 계약검토 ID·원문 해시 등 명시적 연결을 우선함. 제목·부서·상대방·일자는 후보 검색에만 활용하고 유사성을 동일성으로 간주하지 않음.
- 기존 검토이력에 실제 본문이 있는지, 첨부명·경로만 있는지 구분함. 근거 없는 자동 복원을 약속하지 않음.
- 분석·화면 전환·판정 저장·평가 실행 시간을 각각 계측함. 데이터 크기, 브라우저, 장비 조건을 함께 기록함.
- 완료 기준: 같은 파일 재적재 시 중복 없음, 판정 수정 시 최신 결과 반영, 구자료 손실 없음, 연결 불명 사례의 오병합 없음, 성능 기준값 확보.

### 2단계 — 결론·근거 자동태깅

- 사용자가 선택한 이상없음·검토의견·해당없음은 추론 없이 확정 결과로 저장함.
- 체크항목과 사용자 의견에서 쟁점, 판단 이유, 충족 경로, 조건, 예외를 추출함. 태그별 원문 구간·추출 방식·태그 엔진 버전을 기록함.
- 내용 충족, 본문·별첨 결합 충족, 해당없음, 위험 수용, 이유 미상으로 판단 성격을 구분함. 명시되지 않은 이유는 미상으로 남김.
- 원래 사용자 문구와 판정은 불변 이력으로 보존함. 생성된 분류를 사용자 직접 입력으로 표시하지 않음.
- 과거 코퍼스는 의견별 판단 패턴으로 태깅함. 연결이 복원된 경우에만 계약별 판단으로 승격함.
- 향후 판정 확정·의견 수정 시 해당 항목만 태깅함. 자동판정 출력은 사람 확정 결과와 구분하고 반복 수입으로 신뢰도가 증가하지 않게 함.
- 폐쇄망 기본 동작은 외부 API 없는 로컬 규칙·사전 기반으로 구성함. 선택적 내부 모델 연동은 별도 환경이 확인된 경우에만 검토함.
- 완료 기준: 부정·조건부·위험수용 의견을 무조건 충족으로 분류하지 않음, 이유 없는 이상없음에 근거를 생성하지 않음, 수정 후 태그 갱신, 사용자 추가 입력 없이 기본 작동.

### 3단계 — 태깅·코퍼스 결합 매핑

- 문서의 주제·업무·역할·개인정보 처리 정보와 판단 태그·근거 문장을 함께 검색함.
- 부서는 보조정보로만 사용하고 부서별 구 유형을 정답으로 고정하지 않음.
- 계약검토 자료는 특정 문서의 판단 근거로, 법률검토 자료는 적용 조건·예외를 보완하는 자료로 구분함. 같은 원천이 양쪽에 있을 때 한 사례로 계산함.
- 사람이 근거 조항을 지정·수정한 기록과 판정만 확정한 기록을 구분함. 후자를 매핑 정답으로 자동 승격하지 않음.
- 동일 주제라도 주체, 의무 방향, 사전·사후 조건, 책임 제한이 다른 사례는 구분함. 관련성 낮은 참고자료 때문에 해당 체크를 보류시키지 않음.
- 제거된 체크항목을 과거 태그 때문에 재활성화하지 않음.
- 완료 기준: 올바른 조항 탐색률 개선 여부 확인, 잘못된 조항 직접 연결과 중요한 쟁점 누락의 회귀 없음, 자료별 기여 출처 확인 가능.

### 4단계 — 자동판정 보류 해소

- 문서 전체의 예외·정의문 일괄 차단을 해당 쟁점의 근거·정의·참조·우선적용 조항 검사로 대체함. 계약 전체에 효력이 있는 제한은 계속 확인함.
- 일반 서술형 계약 표현, 정의된 당사자 명칭, 여러 문장으로 나뉜 요건, 본문·별첨의 결합 근거를 처리함.
- 계약기간, 지급·정산, 분쟁해결·관할 등 확인 요소가 명확한 항목부터 적용함. 항목 전체 요건이 충족되지 않으면 부분 확인만 표시함.
- 표준약정서는 실제 포함 여부·내용·버전·적용 범위·변경·우선관계를 확인하여 관련 항목을 함께 처리함. 파일명이나 적용 체크박스만으로 통과시키지 않음.
- 해지권·손해배상은 회사 역할과 권리·책임 제한을 포함한 좁은 조건부터 확장함. 위험수용 사례는 일반 자동통과 규칙에서 제외함.
- 같은 근거가 여러 체크를 충족할 수는 있으나 서로 다른 질문을 일괄 병합하지 않음.
- 완료 기준: 근거가 명확한 양성 시험의 보류 감소, 관련 없는 예외에 대한 불필요한 차단 해소, 주체 반전·부정·단서·별첨 누락 등 반례의 잘못된 통과 없음.

### 5단계 — 평가 기본설정·화면·성능 개선

- 자료 반입 화면에서 코퍼스·계약검토·법률검토의 연결 수, 근거 확보 수, 연결 미확정 수를 요약함.
- 일반 흐름을 자료 불러오기 → 자동 준비 → 누적 검토 기준 점검 → 충돌만 확인으로 단순화함.
- 계약 계열은 자동 후보 분류하고 불명확한 경우만 확인받음. ID 입력·분할 설정·전문 승인 원장은 고급 화면으로 이동함.
- 기존 확정 이력을 기본 회귀 정답으로 활용함. 독립 검증된 시험자료와는 구분하고, 모든 사례를 다시 이중 채점하도록 요구하지 않음.
- 출력은 자동처리 확대, 과거 확정판정과 충돌, 근거 부족으로 구분함. 고급 설정을 숨기는 것이 안전조건 해제를 뜻하지 않도록 함.
- 태그·검색색인은 적재 시 계산하고 변경분만 갱신함. 무거운 작업은 검토 UI와 분리하여 취소·진행 표시·중복 실행 방지를 제공함.
- 자료·태그·엔진 버전 변경 시 관련 캐시를 무효화함. 태그 생성 실패 시 판정 저장 자체는 유지하고 미처리 상태를 표시함.
- 완료 기준: 기본 평가에 계약 계열 ID 직접 입력 불필요, 확인할 충돌만 접근 가능, 기존 검토 저장·완료·리포트 상태 일치, 같은 환경의 주요 조작 지연 회귀 없음.

## 별첨 2. 평가 방법 및 출시 조건

### 비교 구성

- v1.64 기준, 보류 로직만 개선, 기존 태깅 추가 활용, 코퍼스 판단태깅까지 결합한 구성을 동일 사례에서 비교함.
- 원문 없는 집계자료는 후보 우선순위에만 사용하고 실제 판정 시험 분모에 넣지 않음.
- 개발에 활용한 계약 및 동일 양식 계열을 시험 참고자료에서 제외함. 시점·문서 버전도 구분함.
- 실제 확정 사례와 합성 반례를 구분하여 보고함. 자동판정 출력의 반복을 새 정답으로 세지 않음.

### 성과 지표

- 자동 이상없음 처리율: 고정된 비교 범위의 실제 적용 대상 체크 중 자동 이상없음 수 / 적용 대상 체크 수.
- 잘못된 자동통과율: 자동 이상없음 중 검증된 정답이 문제 있음인 수 / 정답 확인 가능한 자동 이상없음 수. 미확정 사례는 별도 표시함.
- 보류 해소율: 기준 버전에서 보류되고 정답상 충족인 항목 중 개선판에서 정확히 자동처리된 비중.
- 매핑: 최초 추천의 정확성, 올바른 근거 포함률, 잘못된 직접 연결 및 중요 쟁점 누락 수.
- 해당없음·중복 정리로 감소한 검토량은 자동 이상없음 처리율과 분리함.
- 속도: 분석·판정 저장·화면 전환·평가 실행의 중앙값 및 상위 지연 구간을 동일 조건에서 비교함.
- 개선율 목표치는 원문 연결과 기준 측정 이후 설정함. 과거 이상없음 82.4%를 목표 자동판정률로 전용하지 않음.

### 출하 전 필수 시험

- 데이터: 구 백업 가져오기, 중복·수정 재적재, 태그 버전 변경, 백업·복원, 부분 실패.
- 판단: 의무 부정, 당사자 반전, 수용 가능한 위험, 조건부 의견, 관련·무관 예외, 누락·변경된 별첨, 상충하는 우선조항.
- 문서: HWP·HWPX·DOCX·PDF 추출과 본문·별첨 구역 회귀시험. 추출 불량을 정상 근거로 취급하지 않음.
- 운영: 판정 수정 후 화면·리포트·검토완료 상태 일치, 오판 발견 시 해당 규칙 범위 정지 및 이전 결과 추적.
- 시험에서 확인된 잘못된 자동통과는 해결 전 해당 범위를 활성화하지 않음. 오류 0건 관측은 실제 오류율 0의 보장으로 표현하지 않음.

### 폐쇄망 반입·확인

- 사용자 코퍼스를 공용 HTML·기본 배포 ZIP에 내장하지 않음. 사용자 자료는 별도 로컬 반입 방식으로 유지함.
