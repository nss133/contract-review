# 매핑·자동판정 신뢰성 개선계획

작성일: 2026-09-09 · 기준: 현재 v1.53.0 작업트리 · 상태: 구현 전 검토안
Work ID: CW-20260825-EF96D7EB

후속 구현: 같은 날 v1.54.0으로 P0 안전 관찰 모드와 P1 내부 평가 기반을 구현했다. 아래는 원래 계획을 보존한 것이며, 실제 완료 범위와 미구현 항목은 [1단계 구현 안내](safe-auto-verdict-v1.54.md)를 따른다. 폐쇄망 실자료 성능 검증·자동허용 승인·전체 계획 완료는 아니다.

## 1. 결론과 우선순위

목표는 자동판정 비율의 최대화가 아니라, 문제가 있는 항목을 자동 이상없음으로 처리하는 오류를 먼저 억제하면서 검증된 범위의 자동화를 넓히는 것이다.

권고 순서는 다음과 같다.

1. 자동 이상없음의 모든 진입 경로를 감사하고 승인된 체크별 허용목록으로 통제한다.
2. 현재 조항의 요건 충족뿐 아니라 단서·반대 조항·별첨·변경합의와의 충돌까지 검사한다.
3. 폐쇄망 원본·태그·검토이력을 연결해 사람 검증 정답셋을 만들고, 같은 폐쇄망 안에서 평가한다.
4. 태그와 과거자료는 적용범위·검색·조항 재정렬을 보조한다. 과거 이상없음 결론은 본건의 정답으로 복사하지 않는다.
5. 안전 기준을 충족한 체크·계약 조건 조합만 단계적으로 자동화한다. 미확인·충돌·표본 부족은 사람에게 남긴다.

지금은 전체 자동 이상없음을 신뢰할 수 있다고 보증할 근거가 부족하다. 기존 테스트 통과는 구현 회귀 방지의 근거이지, 폐쇄망 실자료의 법적 오판율 증명이 아니다. 오류가 절대 없어야 하는 범위는 사람의 최종 확인을 유지한다.

이번 작업에서는 계획과 읽기 전용 진단만 수행했다. 실행 코드·지식 규칙·배포파일은 변경하지 않았다. 폐쇄망 데이터에 접속하거나 반출하지 않았다.

## 2. 현재 코드에서 확인한 사항

| 확인 사항 | 확인 근거 | 신뢰성 측면의 의미 |
|---|---|---|
| 일부 참고 체크는 별도 문장 충족 규칙 없이 확정 매칭만으로 자동 이상없음 가능 | src/verdict.js의 canAutoPass, src/app.js의 applyAutoVerdicts | 관련 조항 발견과 요건의 충분성이 혼재함 |

| 기존 요약 내보내기에 case id·자유기재 desc가 포함됨 | src/goldset.js의 summaryText | 본문이 없다고 비민감 자료라고 볼 수 없음. 이번 조건에서는 내부 전용으로 취급해야 함 |

### 합성 반례로 확인한 검사기의 한계

실계약이 아닌 다음 문장을 구성요소 단위로 시험했다.

> 해지 시 30일 전에 서면 통지한다.
> 다만 상대방은 통지 없이 즉시 해지할 수 있다.

CMN-09의 현 문장요건과 같은 설정(해지 + 최고/시정/통지 + 기간)을 Sentence.evaluate에 넣으면 첫 문장에서 ok:true가 반환되었다. 이 결과와 addressed 상태를 canAutoPass에 전달하면 참고 체크의 자동통과가 true였다.

이것은 전체 앱의 실제 사건 오판 재현이나 위 문구의 법률적 부적정 확정이 아니다. 앞의 통지 요건과 예외의 관계를 해소하지 않아도 두 구성요소가 통과할 수 있다는 진단이다. 전체 앱 재현 회귀를 P0에 추가한다.

## 3. 판정 의미와 안전 관문

매핑의 정답은 ‘어느 문장들이 어떤 체크를 다루는가’이고, 자동판정의 정답은 ‘본건의 이 체크 범위에서 추가 수정·확인이 불필요한가’이다. 두 문제를 하나의 점수로 해결하지 않는다.

처리 흐름:

원본·추출품질 확인 → 유형·역할·적용범위 확인 → 조항 후보 검색 → 체크별 요건 검증 → 계약 전반의 반대근거 검사 → 자동 허용정책 확인 → 자동 이상없음 또는 사람 검토

자동 이상없음은 아래 관문을 모두 통과해야 한다.

| 관문 | 필요한 확인 | 실패·불명확 시 |
|---|---|---|
| 원본·품질 | 검토 버전, 본문·별첨·표의 추출완전성, 문서 간 관계 | 추출/원본 확인 |
| 적용범위 | 거래성격·당사 역할·조건·규제 적용의 충분한 근거 | 적용 여부 확인. ‘신호 없음’을 비적용으로 바꾸지 않음 |
| 직접 근거 | 본건의 정확한 문장·문서·조항 위치 및 체크와의 관계 | 관련 원문 확인 |
| 요건 충족 | 주체·행위·대상·조건·시점·기간·예외 등 해당 체크가 요구하는 전 요소 | 미충족 요소를 특정하여 사람 검토 |
| 반대근거 | 단서, 다른 조항, 우선순위 약정, 별첨·변경합의의 상충 여부 | 상충 지점 검토. 단서가 있다는 이유만으로 위법 단정은 하지 않음 |
| 허용정책 | 체크·문구/거래 조건·정책 버전이 승인된 자동화 범위 안인지 | 자동판정 보류 |
| 유효성 | 판정 시점의 입력·규칙·근거 지문이 지금도 같은지 | 기존 자동판정을 재확인 대상으로 전환 |

‘관련 조항 있음’, ‘문장 요소 있음’, ‘이 체크에 자동 이상없음’, ‘계약 전체 검토 완료’를 별도 상태로 둔다. 한 체크의 통과를 계약 전체 안전성으로 표시하지 않는다. 개별 체크가 모두 자동완료되어도 적용범위 미확인·자유 쟁점·추출 실패가 남으면 전체 완료로 집계하지 않는다.

## 4. 자동판정 정책 개편

### 4.1 허용목록과 단일 판정 관문

- 참고/권장 같은 중요도만으로 자동판정 자격을 부여하지 않는다. 참고 체크도 복잡한 판단일 수 있다.
- 기본은 자동완료 불허. 검증된 체크와 적용 조건의 조합에 한해 허용한다.
- 일반 자동판정, 회사에 유리하다는 관점 판정, 표준부속서류 일괄 반영, 이전 검토 승계 등을 전수 목록화한다. 순수 사람 클릭은 유지하되 자동 생성/승계 판정은 같은 안전 관문을 거치게 한다.
- 각 허용 규칙은 판단 질문, 필수 요소, 적용 조건, 반대·보류 조건, 근거 자료 범위, 검증셋 버전, 승인자·승인일을 가진다.
- 항목별 스위치와 전역 자동판정 중지 스위치를 마련한다. 매핑·근거 안내 기능은 중지하지 않아도 된다.

### 4.2 처음 자동화할 범위

- 우선 검토 후보: 조직이 승인한 표준문구가 유효한 동일 범위에서 사용되고, 필수 가변값·당사자·기간·모순 여부까지 확인할 수 있는 좁은 체크.
- 존재 확인만 가능한 항목은 ‘근거 확인’까지만 자동화한다. 체크 질문이 충분성·공정성까지 요구하면 존재 확인 결과를 이상없음으로 승격하지 않는다.
- 초기 사람 검토 유지: 해지권 균형, 손해배상 범위의 적정성, 책임 제한·면책, 독점·경업 제한, 복합 규제 해당성, 새로운 거래 유형, 미확인 외부 사실, 문언 간 상충.
- 표준약정이라는 파일명이나 사용 체크박스만으로 문서화·체결·공개·통지 의무를 함께 충족했다고 하지 않는다. 각 의무에 필요한 증거가 다르다.
- ‘해당사항 없음’ 역시 별도 승인 기준이 필요하다. 키워드가 없다는 이유로 자동 비적용·이상없음 처리하지 않는다.

### 4.3 판정 근거 기록

자동판정마다 체크 ID/버전, 본건·별첨 지문, 조항/문장 위치, 확인한 요소, 해소한 예외, 보류검사 결과, 정책 버전, 생성 주체를 묶은 증거 기록을 남긴다.
원본·별첨·유형·당사 역할·재지정·규칙이 바뀌면 관련 자동 기록을 무효화하고 재평가한다. 이전 기록은 감사이력으로 보존한다.
사람 판정을 자동 삭제하거나 덮어쓰지 않는다. 전제 변경 시 기존 사람 판단에는 ‘변경 후 재확인 필요’를 붙인다.

## 5. 폐쇄망 데이터 활용 설계

### 5.1 데이터 등급부터 확인

사용자가 원본·태그를 적재했다는 점은 전제로 하되, 현재 개발 환경에서 실제 연결·품질·완전성을 확인한 것은 아니다. 폐쇄망 내부 진단 화면에서 다음을 집계한다.

| 확보 상태 | 허용 용도 | 금지할 해석 |
|---|---|---|
| 부서·제목·요청내용·태그만 있음 | 후보 검색, 용어 정규화, 유형·쟁점 보조 | 법적 충족의 정답 |
| 태그와 근거 문장 있음 | 해당 문장의 출처·역할 검증 후 매핑 보조 | 결과 의견 문장을 계약 조항으로 취급 |
| 계약 원문·문서 버전·조항 연결 있음 | 조항 검색·재정렬 학습/평가 | 과거 검토결론을 현재 문언의 정답으로 승계 |
| 해당 원문에 대한 사람의 체크별 확정 판단까지 있음 | 검증을 거친 자동판정 정답 후보 | 문서 전체 ‘이상없음’을 모든 체크의 이상없음으로 복제 |
| 수정 전후와 재검토 경과까지 있음 | 오류 대비쌍, 수정사항 재현, 변경 검증 | 수정 후 결론을 수정 전 문서에 붙임 |

신청·검토결과·계약본문·별첨의 출처를 분리한다. ROW-2 같은 행 ID는 파일 내 식별자이고, 계약군의 동일성은 별도로 확인한다. 중복·재업로드·개정본이 사례 수와 정확도를 부풀리지 않게 한다.
금액·부서는 필요한 맥락과 층별 성능평가에 사용하되, 작성자·신청자 개인 이름은 판단 특징이 아니라 권한·감사 정보로 둔다.

### 5.2 매핑 개선에 쓰는 방법

1. 현행 어휘 검색 + 태그 정본·동의어 + 조항 표제·역할로 후보를 회수한다. 제목·부서만으로 후보군을 잘라 실제 적용항목을 놓치지 않게 한다.
2. 문장을 ‘누가 / 무엇을 / 누구에게 / 어떤 조건으로 / 언제 / 허용·의무·금지 / 예외’ 구조로 비교한다. 미추출 요소는 unknown으로 둔다.
3. 같은 체크의 수정 필요 사례·불충분 사례를 함께 검색한다. 정상 사례만 가까이 모아 검색 편향을 만들지 않는다.
4. 과거 태그는 그 태그의 본건 근거 위치를 다시 찾는 데 사용한다. 이전 계약의 점수·빈도·최종 결론은 자동완료 점수를 올리지 못한다.
5. 조항 재지정과 ‘이 조항이 맞음’ 피드백을 수집한다. 재지정은 매핑 정답이지 이상없음 정답은 아니다.
6. 1개 체크에 여러 조항이 필요한 경우 근거 집합을 보존한다. 한 조항에 여러 법적 요건이 있는 경우도 각각 검증한다. v1.53.0의 표시 묶음은 판정 병합으로 확대하지 않는다.

검색 점수와 자동판정 신뢰도는 별도 필드다. ‘매칭 95점’을 ‘법적으로 95% 안전’으로 표시하지 않는다.
선택형 내부 임베딩 검색·재정렬 모델은 어휘 기반 대비 실측 후 도입한다. 모델 설치가 불가능하면 규칙·정본·사람 피드백만으로 먼저 진행한다.

### 5.3 과거 판단의 정답화

- 원본 버전과 판단 시점이 맞는지 먼저 확인한다. 현행 규칙으로 과거 자료를 평가할 때는 과거 당시의 정당성과 현재 기준의 적합성을 구분한다.
- 자동 기재, 표준서식 일괄 기재, 이전 판정 복사, 사람 독립 판정을 구분한다. 자동 결과가 그대로 남아 있다는 이유로 사람 검증 정답으로 인정하지 않는다.
- 라벨은 적용 여부, 관련 조항 집합, 요건별 충족/불충족/미확인, 최종 조치, 판단 근거로 나눈다.
- 판단되지 않았거나 검토 범위 밖인 항목은 미라벨이다. 검토의견이 없다는 이유로 음성/안전 사례로 채우지 않는다.
- 오자동 의심·판단 충돌·중요 경계사례는 2인 검토와 조정으로 확정한다. 자동 결론을 먼저 보지 않는 검토를 포함해 동조 편향을 줄인다.

## 6. 반출 없는 운영 구조

기본안은 데이터·통계 모두 무반출이다. 태그·원문·근거문장·식별자·해시·스크린샷·로그·임베딩·학습 가중치·사례에서 얻은 규칙도 자동 반출하지 않는다. 익명화나 집계만으로 반출이 허용된다고 가정하지 않는다.

외부 개발환경: 공개·독립 합성 문장으로 엔진·평가기·내부 관리화면 개발 → 승인된 업데이트 파일 반입

폐쇄망 내부: 원본 연결 진단 → 정답 검수 → 기준선/후보버전 동시 평가 → 실패사례 확인 → 선언형 규칙 수정·승인 → 제한 적용·모니터링

- 동일 웹앱에 오프라인 평가 실행기·검수 큐·체크별 정책 편집기를 탑재한다. 실자료를 저장소에 반입하거나 콘솔로 덤프할 필요가 없게 한다.
- 규칙 편집은 키워드 추가만이 아니라 필수 요소·주체·금지조건·허용 문구·범위를 선언형으로 관리한다. 임의 JavaScript 실행을 허용하지 않는다.
- 내부 규칙 오버레이는 앱 업데이트와 분리 저장하고, 호환성 검증·승인·롤백·백업을 제공한다. 승인되지 않은 자동 학습 결과는 운영 규칙으로 올리지 않는다.
- 원문 접근권한은 내부 PC/공유폴더·계정 정책으로 통제한다. 현재 브라우저 로컬 저장만으로 조직 수준 접근통제·감사를 완성했다고 보지 않는다.
- 기존 ‘반출용 요약’은 기본 사용 중지/내부 전용으로 명명하는 개선을 계획한다. case ID·자유서술 desc 등 우회 노출을 검사한다.
- 조직에서 별도 승인한 경우에만 지정된 집계 통계 또는 독립 합성 반례를 공유하는 선택 경로를 검토한다. 현재 사용자 요청을 그 승인으로 간주하지 않는다.
- 반출 승인이 전혀 없더라도 내부 평가·정책 조정·승격은 완료할 수 있게 한다. 외부에서 실자료 성능을 확인할 수 없다는 한계는 유지한다.

과거 문서의 ‘원본/코퍼스 반출 후 외부 튜닝’ 계획은 이번 과제에 적용하지 않는다.

## 7. 평가 설계와 합격 기준

### 7.1 세 종류의 평가셋

- 개발·튜닝셋: 폐쇄망의 과거 계약·사람 교정. 임계값·규칙 작성에 사용한다.
- 고정 검증셋: 계약군·공통 템플릿 계보·개정본을 통째로 분리하고 시간상 뒤의 계약을 포함한다. 평가 계약군은 과거 검색 인덱스와 튜닝 데이터에서도 제외한다. 정답 결과가 입력에 섞이지 않게 한다.
- 도전셋: 사전동의→사후통지, 주체 반전, 전부→일부, 기간 삭제, 예외 추가, 모순 별첨, 수정 전후, 참고문구를 실제 의무처럼 인식하는 경우, 문서 누락·추출 실패 등을 포함한다. 실제 업무 분포 추정에는 섞지 않고 별도 보고한다.

초기 작업량 제안: 내부에서 100~200개 계약군을 층화하여 기준선을 만들고, 우선 자동화 후보 5~10개 체크의 근거·반례를 집중 검수한다. 이는 착수용 규모이지 안전성을 입증하는 충분 표본 수가 아니다.
자동 후보뿐 아니라 수동 보류·quiet·비적용 처리된 사례를 표집해 놓친 실제 문제도 확인한다. 초기에 자동 후보는 전수 사람 대조하고, 안정화 후에도 무작위 표본과 고위험 사례 전수를 함께 감사한다.

### 7.2 핵심 지표

| 지표 | 정의·용도 |
|---|---|
| 오자동 이상없음률 | 사람 검증상 문제 있음에도 자동 이상없음인 건수 / 자동 이상없음 건수. 최우선 |
| 미검증 자동완료율 | 사실 미확인·정답 미확정인데 자동완료한 건수 / 자동 이상없음 건수. 틀렸는지 불명이라고 정답으로 빼지 않음 |
| 실제 문제 누락률 | 실제 문제인데 검토 필요로 드러나지 않은 건수 / 검증된 실제 문제 건수. 잘못된 비적용·quiet·체크 미선정 포함 |
| 매핑 Recall@3·Top-1 | 사람 검증 근거를 후보 안에 회수했는지 / 1순위가 올바른지. 여러 근거가 필요한 체크는 근거집합 충족도도 측정 |
| 자동완료율 | 자동완료 건수 / 평가대상 적용 체크 건수. 적용 여부 미확정과 분모 정의를 별도 공개 |
| 검토 비용 | 확인·정정·재작업·라벨링을 포함한 시간, 클릭 수, 사람 반전률 |

체크별·계약군별·역할별·표준/비표준별·자료완전성별·버전별로 분리한다. 총평균이 나쁜 하위집단을 가리지 못하게 한다. 사람이 수정한 비율은 감시지표이며 숨은 오류율의 대체값이 아니다.

### 7.3 ‘0건 오류’ 해석

검증셋에서 오류가 없다는 것만으로 실제 오류율 0%를 보증하지 않는다. 고정된 정책에 대해 독립·동일 분포 표본에서 오류 0건일 때 이항모형의 단측 95% 오류율 상한은 1 − 0.05^(1/n)이다.

- 55건에서 0오류: 상한 약 5.30%.
- 300건에서 0오류: 상한 약 0.994%.
- 2,995건에서 0오류: 상한 약 0.100%.

이 수치는 수식 예시이지 사용자에게 허용 오류율 0.1%를 제안·확정한 것이 아니다. 같은 계약의 여러 체크나 반복 템플릿을 독립 표본처럼 세지 않는다. 계약군 단위 분석/표집과 층별 불확실성을 함께 보고한다. 동일 시험셋을 반복 보며 임계값을 고르면 위 상한을 그대로 적용할 수 없으므로 최종 보류셋을 별도로 둔다.

### 7.4 출시 관문 제안

1. 알려진 중대 오자동 반례 0건, 중요한 검토사항 누락 회귀 0건을 필수 조건으로 둔다.
2. 검증 중 실제 문제가 있는 자동 이상없음이 1건이라도 확인되면 해당 규칙/범위의 승격을 중지한다. 이미 적용 중이면 그 범위의 자동완료를 정지하고 영향사례를 내부 재검토 큐로 보낸다.
3. 체크·범위별 목표 오자동 오류율 상한과 허용 잔여위험은 내부 법무 책임자가 승인한다. 표본이 부족하거나 기준이 미정이면 그림자 평가/사람 확인 모드를 유지한다.
4. 자동완료율 상승은 위 안전 관문을 통과한 뒤에만 채택한다. 모든 것을 보류해 오류율만 낮추는 경우는 효율 개선으로 보고하지 않는다.
5. 초기 운영에서는 필수·고위험·복합 판단의 사람 확인을 유지한다. 그 외 범위도 좁은 허용목록부터 확대한다.

| 단계 | 구현 산출물·담당 | 완료 기준 |
|---|---|---|

| P3 그림자 평가 | 폐쇄망: 실제 판정은 사람이 수행하고 자동 후보를 뒤에서 채점 | 후보 전수 대조, 하위집단 평가, 반례 수정, 별도 보류셋 검증. 반출 없이 내부 대시보드로 승인 |
| P4 제한 운영 | 법무 책임자: 허용목록 승인. 개발/운영: 범위별 설정·버전 고정·재검토 큐 | 승인된 범위만 자동 이상없음. 새 유형·규칙/법령 변경·미확인 입력은 자동 보류 |
| P5 지속 점검 | 내부 운영: 무작위 감사·신규 반례·분포 변화·규칙 폐기/롤백 | 오자동 발견 시 중지·영향도 조사·재검증 후 재승인하는 이력 유지 |

실제 일정은 내부 검수자 가용시간·자료 연결률·설치 제약을 확인한 뒤 산정한다. 자동화 비율 목표를 먼저 정하고 안전 기준을 낮추지 않는다.

## 9. 첫 구현 묶음 권고

우선 P0와 P1을 함께 구현하는 것이 적절하다. 임계값 상향이나 태그 가산점 확대를 단독으로 먼저 하지 않는다.

- 기존 53개 참고 체크 후보와 모든 일괄·승계 경로를 내부 감사목록으로 표시.
- 자동판정 허용/그림자/금지 상태를 체크별로 관리.
- 본칙·단서·다른 조항·별첨의 불일치를 자동완료 차단사유로 기록.
- 과거 이력의 원본 연결·판정 출처·수정 전후를 확인하는 내부 진단.
- 오자동 이상없음과 문제 누락을 직접 측정하는 평가 대시보드.
- 사람 판정을 독립 정답으로 확정하는 검수 화면 및 버전 고정.

이 단계의 성공은 자동 이상없음 수 증가가 아니라, 무엇을 근거로 자동판정했는지 설명·재현하고 잘못된 자동판정을 내부에서 발견·차단할 수 있게 되는 것이다.
