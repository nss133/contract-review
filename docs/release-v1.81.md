# v1.81.0 — 보안 요건 자동판정·복합 문장·별첨 참조 확대

## 이번에 구현한 범위

- 현재 체크리스트와 일치하는 직접 판정 규칙이 있는 질문은 24개에서 34개로 늘었습니다. 관련 조항·조건을 비교하여 사용자 판단을 재사용하는 질문은 26개에서 36개로 늘었습니다. 이는 질문 종류 수이지 모든 표현의 인식률이나 실제 자동판정률이 아닙니다.
- 추가된 보안·IT 질문은 ITSEC-01~09 및 ITSEC-13입니다. 업무장소·설비 분리, 암호화정보 해독·중요 데이터 변경 금지, 금융정보 무단보관·유출 금지, 보안대책, 전용회선, 비상대책, 단계별 보안관리, 백업대책, 재무건전성 평가·상시 모니터링 자료, 보안성검토·정기점검 협조 약정의 존재를 확인합니다. 실제 이행 여부는 판단하지 않습니다.
- 각 질문이 요구하는 구성요소를 모두 확인합니다. 예를 들어 백업은 자료 보존과 설비 확보, 재무건전성은 연 1회 이상 평가와 상시 모니터링 자료 협조를 함께 확인합니다. 가상 전용회선은 동등한 보안수준이라는 약정까지 필요합니다. 금지·의무·재량, 주체, 평가 횟수를 지우지 않습니다.
- 명시적인 이행 약속 종결형과 일부 목록 순서 변형을 동등하게 읽습니다. 한 문장에 병렬로 적은 의무는 최대 6개까지 각각 읽어 분리 문장과 비교합니다. 읽지 못한 가지나 새로운 조건을 버려서 통과시키지 않습니다. 기존 태그와 함께 주체·대상·행위·조건·횟수를 근거에 표시하며 표준 비교와 과거 판단 재사용에도 연결합니다.
- 본문과 별첨에서 제1조가 다시 시작되는 경우 번호 영역을 분리합니다. 번호가 명시된 별첨을 같은 파일의 별첨 구역 또는 별도 파일에서 찾고, 내부 조문 및 본문 역참조를 연결합니다. 참조된 별첨 전체와 역방향 제한 조항도 비교합니다. 빠진 별첨, 같은 번호의 중복 별첨, 비어 있는 자료는 임의 선택하지 않습니다.
- 직접 요건 판정도 참조 관계를 검사합니다. 다른 조에서 핵심어 없이 ‘제N조의 의무’만 가리켜 제한하는 특약을 놓치지 않도록 했습니다. 별첨의 같은 조문 번호를 본문에 대한 제한으로 오인하지 않게 구분합니다.
- 외부 규정의 별표와 계약 첨부를 구분합니다. 외부 규정의 내용을 새로 해석하지 않으며 등록 표준과 같은 참조 문구·전체 문맥을 보존하는 기존 경로만 사용합니다. 일반 과거 판단에는 이 예외를 적용하지 않습니다.
- 기존 자동 등록 표준은 연결 규칙 9로 자동 갱신합니다. 재승인은 필요하지 않으며 사용 중지·수동 설정을 보존합니다. 자동판정은 기존 ② 확인 완료 열에 반영합니다. 최신 사용자 정정·관련 예외가 있으면 철회하고 직접 입력한 판정은 덮어쓰지 않습니다.

## 검증 범위

Node 771개·Python 106개, 총 877개 회귀시험을 통과했습니다. 신규 보안·별첨 참조 흐름과 기존 관련 표준·표준 등록·의무 요소/출처 연결·과거 판단·판정 생명주기·표준 라이브러리·표준 비교 확대·체크리스트 내용의 브라우저 10개 흐름을 검증했습니다.

합성 계약에서 신규 10개 질문의 실제 자동판정·②열 이동, 4개 병렬 의무, 별첨을 통한 사용자 정답 재사용, 약정 기간·평가 횟수·번호 참조 특약 변경 시 철회, 사용자 정정 우선 및 직접 입력 보존을 확인했습니다. 시험한 앱 흐름에서 외부 통신과 런타임 오류는 없었습니다. 합성 원문 시험은 독립 실계약 정확도 측정이 아닙니다.

실제 보안관리약정서 3종에 무관한 조항을 추가하는 기존 비교의 판정 수는 GA 3개·일반 6개·재위탁 6개로 유지됩니다. 공개 양식·해설서 5종의 직접 자동충족 수는 여전히 0개입니다. 이 자료들에서 새로운 증가가 있었다고 주장하지 않습니다. 보유 추출 텍스트 기반 시험으로 HWP·HWPX·DOCX·PDF의 모든 변환 품질을 보증하지 않습니다.

## 적용 방법

기존에 사용하던 실행기에서 contract-review-v1.81.0.crupdate를 적용하고 계약을 재분석합니다. 실행기 경로·이름과 브라우저 프로필을 유지하고 내부 백업을 보관하십시오. 새 승인·외부 AI·태깅자료 반출은 필요하지 않습니다. 배포본에 사용자 코퍼스나 보안관리약정서 원문을 내장하지 않습니다.

## 전체 계획과 구분되는 잔여 범위

이번 구현 범위는 완료하되 모든 자동화 가능 질문의 임의 표현을 해결한 것은 아닙니다. 현재 존재 질문 60개 중 30개에는 직접 판정 규칙이 없고, 등록 표준·출처가 확인되는 사용자 판단 재사용 경로와도 구별해야 합니다. 개발용 범위 점검은 build/audit_auto_coverage.cjs로 재현할 수 있습니다.

번호·제목이 모호한 별첨 선택, 별첨마다 다른 갑·을 정의, 복잡한 예외 우선순위의 해석, 자유로운 의역은 여전히 추가 개발 또는 사람 판단 대상입니다. 폐쇄망의 실제 자동판정률·오판율·장비 성능 측정도 별도로 남습니다. 자체 시험의 오류 미발견을 실제 오판율 0으로 해석하지 않습니다.
