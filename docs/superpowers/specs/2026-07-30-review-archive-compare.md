# 재검토 비교 — 검토 아카이브·전년 대비 diff·판정 이관 (설계)

> 2026-07-30 사용자 요청: 검토를 마친 계약을 저장해뒀다가 다음 해 같은 계약이 오면
> 이전 검토와 비교해 달라진 부분만 코멘트하고, 같은/다른 부분을 비교본으로 보는 기능.
> 공수·쓸모·제약 검토 후 승인. 오프라인 단일 파일 원칙 유지(외부 의존 0).

## 개념

- **검토 아카이브(.json)**: 계약 본문 전문 + 판정(verdicts) + 종합의견(opinion) + 메타
  (계약명·유형·해시·검토일·검토자)를 담은 반출 파일. 기존 verdict export의 확장 —
  본문 포함이 차이. 보관은 폐쇄망 내부(현행 보안 모델과 동일 — 계약 텍스트가 기기 밖
  으로 나가지 않는 원칙은 "사용자가 명시적으로 반출한 파일"에는 적용되지 않음을 고지).
- **비교 검토 모드**: 새 계약 분석 후 아카이브를 불러오면 조항 정렬 → 같음/변경/신설/
  삭제 분류 → 비교본 뷰 + 판정 이관.

## 데이터

아카이브 스키마 (기존 verdict export 상위호환 — verdicts·meta.opinion 유지):

```json
{
  "meta": { "type_id", "date", "contract_hash", "reviewer", "opinion",
            "archive": true, "name": "계약명(사용자 입력 가능)" },
  "contract_text": "계약 본문 전문",
  "verdicts": { "cpId": { "verdict", "comment", "date" } }
}
```

- 리포트 내보내기 영역에 "검토 아카이브 저장" 버튼(일상 액션 그룹).
- 불러오기: 리포트 요약 바 또는 입력 화면의 "이전 검토와 비교" — 아카이브 파일 선택.
- localStorage는 쓰지 않음(브라우저·PC 종속·용량 제약 — 제약 검토 결론).

## 조항 정렬 (핵심)

- 구(아카이브)·신(현재) 계약을 각각 segmentContract로 분할 후 조항 단위 매칭:
  1. 조번호+표제 완전 일치 → 직결.
  2. 잔여는 sim.js(char_wb TF-IDF 코사인) 전 쌍 유사도 → 임계 이상 최적 매칭(greedy).
  3. 매칭 유사도 구간: ≥0.95 "동일" / 0.60~0.95 "변경" / 미매칭 신규 조항 "신설" /
     미매칭 구 조항 "삭제". 조번호가 다른데 내용 매칭이면 "이동" 병기.
  4. 임계·greedy 한계로 오정렬 가능 — "대응 불확실" 표시를 두고 확정하지 않음.
- 텍스트 diff: "변경" 조항에 한해 어절 단위 LCS diff(바닐라 구현, 공백 정규화 후) —
  추가분 하이라이트(신), 삭제분 취소선(구).

## UI — 비교본 뷰

조항별 검토 탭 확장(비교 모드 토글 시): 행 grid에 구 계약 열 추가.

```
[비교 모드 헤더] 전년 검토(2026-07-30, 손남수) 대비: 동일 18 · 변경 4 · 신설 2 · 삭제 1
┌ 구 계약(전년) ─┬ 신 계약(현재) ─┬ 검토·제안(현행 P2 ②③ 통합) ┐
│ 제7조 …취소선…  │ 제7조 …하이라이트… │ [전년 인용] 이상없음 '…'   │
```

- 동일 조항: 구 열은 "동일" 한 줄로 접지 않고 흐리게(접기 금지 원칙) — 공간은 신 열과
  동일 텍스트이므로 "(전년과 동일)" 플레이스홀더 허용(원문은 신 열에 있음).
- 삭제 조항: 최하단 "구 계약에만 있던 조항" 블록.
- 리포트: 비교 모드 시 종합의견 첫 문장에 "전년(날짜) 검토 대비 변경 N개 조항" 요지
  추가, "변경·신설 조항" 섹션 신설(딥링크).

## 판정 이관

- "동일" 조항에 매칭된 체크의 전년 판정: **자동 확정하지 않고** "전년 검토 인용" 배지 +
  전년 verdict·comment 프리필 → 1클릭 수용(수용 시 date는 오늘, comment에 "(전년 인용)"
  꼬리표). 사유: 문언 동일해도 법령 개정으로 판단이 달라질 수 있음(제약 검토 ③).
- 일괄 수용: "동일 조항의 전년 판정 N건 일괄 수용" 버튼(통과계약 모드와 동형).
- "변경" 조항의 전년 판정은 이관하지 않고 참고 표시만(전년 코멘트를 loop hint 자리에).
- 부재 알람(조항 무관)의 전년 판정도 같은 규칙(체크 id 기준 매칭).

## 구현 노트

- 신규 모듈 src/compare.js (순수 로직: alignClauses·diffWords·carryVerdicts — node 테스트).
- app.js: 비교 모드 상태(state.compare)·비교 행 렌더·이관 UI. JS_ORDER는 sim 뒤·app 앞.
- 아카이브 저장/불러오기는 기존 verdict export/import 코드 경로 재사용·확장.
- 골드셋·매처·지식 무변경 — 30/30 유지가 게이트.

## 제약 고지 (구현 시 UI 문구에 반영)

1. 아카이브 파일에 계약 전문 포함 — 폐쇄망 내부 보관.
2. 조항 정렬은 보조 도구 — "대응 불확실" 항목은 사람 확인.
3. 전년 판정 이관은 인용이지 확정이 아님 — 법령 개정 여부는 별도 확인.
4. 파일 형식이 바뀐 재검토(hwp→docx 등)는 형식적 차이가 diff에 잡힐 수 있음.
