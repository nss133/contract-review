## 컴포넌트

### 1. corpus 백업 투입 (엔진 변경 없음)
`build/curation_report.js`에 백업 투입 → 리포트 산출 → 후보 반영:
- SP-DEL-03 검토의견("불가항력 조항 있으나 계약이행 책임만 규정 — 보완 필요") → 체크 문구·게이트 정교화 후보.
- SP-DEL-10 해당없음("용역 제공 약정이라 신품 요구 해당없음") → 용역계약 전제조건(absence_precondition) 후보.
- ITDL-06 해당없음은 기교정(589e0ea) — 재발 여부만 확인.
- 이상없음 코멘트 22건은 안정 신호로 코퍼스에 병합(멱등).

### 2. 골드셋 사내표준층 — 케이스 16~28
13패킷 → 각 1케이스 (`tests/goldset/cases/`). 라벨:
- `detect_expected`: 기대 유형.
- `consider_must_exclude(_prefix)`: 법무검토 완료 문서이므로 떠서는 안 될 필수 알람.
- `active_must_exclude`: 켜져선 안 될 모듈.

**결정 A (사용자 동의)**: 현행 9유형에 없는 유형(신탁·후원·광고·영업양수도)은 이번에
유형을 신설하지 않고 최근접 유형으로 라벨(광고→조달, 후원→제휴 등). 감지 공백이 크게
확인되면 유형 신설을 후속 과제로 분리. 케이스 라벨 초안은 Claude 작성 → **커밋 전
사용자 확인 게이트** 통과 후 커밋.

### 3. 보안관리약정서 recall 골드셋
골드셋 어서션 신설 `addressed_must_include[]` — 지금 골드셋에 없는 recall(반영 검출) 측면.
- 케이스: 약정서(일반)를 본문 입력 → PRIV 계열 체크 addressed 확인.
- 케이스: 본계약(IT용역 표준) + 약정서를 부속서류로 → `subDocCoverage`가 X-PII 항목
  커버로 잡는지 확인. `build/goldset_runner.js`에 subDocs 입력 지원 추가.
- `build/goldset.py`에 addressed 채점 추가.

### 4. 표준 부속서류 레지스트리 + 참조 감지 (엔진 변경)
실무에선 본계약만 올리는 경우가 많음(사용자 확인) → 참조 문구 감지가 필요.

`knowledge/common.yaml`에 `standard_subdocs` 신설:
```yaml
standard_subdocs:
  - id: SUBDOC-PII
    title: 개인(신용)정보 보안관리약정서
    ref_signals: [보안관리약정서, 보안관리 약정, 개인(신용)정보보안관리약정]
    covers: [PRIV-…, ALL-PII-…]   # 약정서 조문↔체크 대조로 구현 시 확정
```

동작 규칙:
- 본계약 본문에 ref_signal 감지 **且** 해당 부속서류 파일 미업로드 → covers에 속한
  consider 알람 N건을 "별첨 약정서로 커버 예정" 그룹 1건으로 전환. **addressed로 치지
  않음** — "약정서 체결·첨부 여부 확인" 확인항목 1개로 묶고, 증적으로 참조 문구 quote 표시.
- 부속서류 파일 업로드 시 기존 subDocCoverage 매칭 경로 우선(기계 확인이 참조 추정보다 강함).
- UI: 기존 "부속서류 반영" 배지와 구분되는 "별첨 참조" 배지·그룹.

### 5. 형식 점검 모듈 — `src/formal.js` 신설
자체점검체크리스트의 형식 항목 중 룰로 확정 판정 가능한 것만 (오탈자 검출 제외):
- 당사 상호 오기: "미래에셋생명보험㈜/주식회사" 외 변형(미래에셋생명㈜ 등) 감지.
- 빈칸 잔존: `OOO`, `___`, `0000.00.00`, 미기입 "년 월 일" 패턴.
- 체결일자 존재, 상대방 상호 법인형태(㈜·주식회사·유한회사 부재 시 확인 권장).
결과는 매칭 체크리스트와 분리된 "형식 점검" 섹션(통과/확인 2상태). `tests/formal.test.js`로 고정.
지식 YAML이 아닌 코드 상수로 관리(법령 근거가 아닌 사규성 룰이므로 quote 검증 대상 아님).

### 6. 체크리스트 갭 분석 → 신규 체크 후보
13종 체크리스트의 실체 항목 ↔ 기존 지식 대조표 → 미커버 항목을 신규 체크 초안으로:
- 후보 예시: 계열사 계약 여부(내부통제 플래그), 이행(하자)보증보험 유무, 별첨 서류 완비.
- 신규 체크는 `verified:false`로 초안 → 사람 검수 대기열. 산출물: 대조표 문서 + 지식 diff.

## 구현 순서·검증 게이트

| 단계 | 내용 | 게이트 |
|---|---|---|
| P1 | corpus 투입·큐레이션 반영 | 골드셋 15/15 유지 |
| P2 | 사내표준층 케이스 13건 | 라벨 사용자 확인 → 오탐 교정 → 스코어카드 before/after |
| P3 | recall 어서션 + 약정서 케이스 | runner subDocs·addressed 채점 테스트 |
| P4 | 부속서류 레지스트리·참조 감지 | 신규 골드셋 케이스(참조 있는 본계약) + JS 테스트 |
| P5 | 형식 점검 모듈 | tests/formal.test.js |
| P6 | 갭 분석·신규 체크 초안 | validate·enrich 통과, verified:false 표기 |

전 단계 공통: pytest·node --test·빌드 통과 후 커밋, 스코어카드 첨부.
