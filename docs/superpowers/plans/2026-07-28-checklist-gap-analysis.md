# 체크리스트 갭 분석 — 신규 체크 후보 대조표 (2026-07-28)

Task 7 Step 1 산출물. 13종 자체점검 체크리스트(사내 실무팀 작성)를 `knowledge/common.yaml` + `knowledge/types/*.yaml`와 대조하여, 앱이 아직 잡지 못하는 실체적 계약 점검 항목을 찾는다.

## 개요

- 대상 체크리스트: 13종 (`samples/internal-standards/extracted/*체크리스트*.txt`, lease-lessee 포함)
- 방법: 각 체크리스트 항목을 추출 → {형식/프로세스/실체적} 분류 → 실체적 항목만 지식베이스와 대조 → {커버/부분 커버/미커버} 판정
- 판정 결과: 실체적 항목 중 **미커버 4건, 부분 커버 1건**(+ 큐레이션 리포트발 검토의견 1건, PRIV-21 규범층위 검토 1건 별도 포함)
- 나머지 실체적 항목은 대부분 CMN-*(공통) 또는 유형별 checks가 이미 커버함(계약당사자·대금·기간·해지·손해배상·비밀유지·관할 등 공통 골격)

## 방법

1. 13개 체크리스트 원문(`NO. | 체크항목 | 주의사항`)을 항목 단위로 읽고, 다음 3분류로 태깅:
   - **형식**: 상호 표기, 빈칸, 일자, 오탈자, 계약서 구비 여부 등 → Task 6 `formal.js`가 소화
   - **프로세스**: 표준계약서 사용 여부, 법무검토 이력, 품의·협조요청 절차 등 → 앱 범위 밖(사람이 하는 행정 절차)
   - **실체적**: 계약 내용 자체의 법적·재무적 리스크 점검 → 앱 지식베이스 대조 대상
2. 실체적 항목마다 지식베이스를 개념 어휘로 Grep → 매칭 check의 `check` 텍스트를 읽고 분류:
   - **커버**: 기존 check가 실질적으로 동일 쟁점을 다룸 (id 명시)
   - **부분 커버**: 관련 check는 있으나 체크리스트가 요구하는 구체 요소 일부가 빠짐
   - **미커버**: 대응 check 없음
3. 미커버·부분 커버 항목에 대해 신규 체크 초안(귀속·basis·norm_type·severity)을 제안. `severity`는 스키마 도출규칙(`basis: practice`→참고, `norm_type: 강행`→필수, `임의`→권장, `추정/간주/선언`→참고)을 따름.

## 판단 필요 사항 (Step 2 사용자 게이트 상정)

1. **① 계열사 체크의 근거 조문 확정**: 상법 §398과 공정거래법 §45①9호 중 어느 쪽을 1차 근거로 걸지, 혹은 X-RELATED 모듈 안에 "계열사 여부 자체를 묻는 스크리닝 질문"으로 둘지(현재 모듈 screening_question은 있으나 이를 뒷받침하는 checks 항목이 없음) 확정 필요. 두 조문 모두 원문 미대조 상태.
2. **② 하자보증보험 체크의 tier**: it-svc 실제 계약서 샘플이 "이행보증보험有/無" 두 버전으로 존재 — 즉 회사 표준계약서 자체가 선택적 채택 구조. absence_check를 무조건 발동시키면 "이행보증보험無" 버전에서 오탐 유발 가능 → `tier: conditional` 또는 `absence_precondition` 게이트 여부 판단 필요.
3. **③ 별첨 완비 체크 표현**: "물리적 첨부 여부"는 룰 불가이므로 "본문이 별첨을 인용·특정하는가"로 축소한 문구안이 실익이 있는지(이미 SUBDOC 레지스트리가 유사 기능 수행 중이라 중복 우려) 판단 필요.
4. **⑤ SP-DEL-03 분리 여부**: 기존 체크를 수정(문구 확장)할지, 원자 분리(SP-DEL-03-2 신설)할지 — 스키마 원칙(조문 항·호=check 1개)상 분리가 원칙에 부합하나 실익 판단 필요.
5. **⑥ PRIV-21 규범 층위(가장 중요한 판단)**: 현재 PRIV-21은 "신용정보법 §17⑦ — 재위탁 원칙 금지, 금융위원회 인정 시 예외"로 기재. 그러나 pii-agreements(재위탁) 약정서 제5조는 "갑·을 간 재위탁 **제한**, 열거 예외 미해당 시 **원수탁자의 서면 승낙**을 얻어 재위탁 가능"으로 규정 — **금융위원회 인정과 원수탁자 서면승낙은 별개 요건**이다. 약정서가 신용정보법 §17⑦의 예외를 계약(자율규제) 차원에서 구체화한 것인지, 아니면 법령 요건(금융위 인정)과 계약 요건(서면승낙)이 병존해야 하는 것인지 확인 필요. 확인 시까지 두 갈래 선택지:
   - (a) PRIV-21은 현행 유지(법령 차원 재위탁 금지·예외), 신규 체크(PRIV-21-2 등)로 "재위탁 시 원수탁자 서면승낙 조항 존재 여부"를 **계약 실무 차원(basis: practice)** 으로 별도 추가
   - (b) PRIV-21의 `note`에 "실무상 재위탁은 금융위 인정 대신 원수탁자 서면승낙으로 운영되는 사례 있음 — 법령 요건과 계약 관행의 정합성은 별도 확인 필요"라는 보충 문구만 추가, 신규 체크는 만들지 않음
   - 사용자 판단 필요: 법무팀이 실제로 "금융위원회 인정"을 받는 절차를 별도로 운영하는지, 아니면 원수탁자 승낙만으로 재위탁을 허용해온 실무인지에 따라 (a)/(b) 및 severity_override 여부가 갈림.
