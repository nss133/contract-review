# v1.90 구현·수용 기준 — 대량 과거자료 분석 시 화면 응답성

상태: 구현·최종 로컬 수용시험 완료. 기존 v1.89 로컬 통과 기록과 폐쇄망 재발은 구별한다. 이 문서는 합격 기준이며 실제 결과는 [최종 검증 기록](v1.90-validation.md)을 따른다. 실제 폐쇄망 장비의 성능은 미확인이다.

## 고정할 의미

- 체크리스트 206개 정책·활성 184개·약정 확인 62개, 점수·매핑·자동판정 요건은 변경하지 않는다.
- 누적 태깅자료·코퍼스·표준·수기 의견을 삭제하거나 기능을 꺼서 성능을 얻지 않는다.
- 과거 의견은 참고 표현이며 본건의 직접 근거나 자동 허용 티켓으로 승격하지 않는다.
- 기존 검색의 후보 200개 순서, 최장 구절·동점 순서·상위 5개를 보존한다.
- 취소·오류·새 입력으로 무효화된 실행은 자동 완료 판정이나 과거 판정 덮어쓰기를 남기지 않는다.

## 구현

1. 전체 근거 구절 검색기 대신 관련 후보 우선·필요한 구절 지연 생성. 질문마다 전체 구절 상태 배열을 다시 만드는 작업 제거.
2. 화면과 분리된 오프라인 내장 작업 스레드에서 과거 검색 준비와 매핑. 같은 작업의 검증된 참고 결과를 자동판정 쪽에서 공유하되 판정 티켓은 실제 현재 문서 검사에서만 발행.
3. 실제 작업 단계 표시·취소·오류 후 버튼 복구. 입력·표준·자료 변경 시 낡은 결과 폐기. 작업 스레드 불가 시 화면에서 무거운 동기 계산으로 돌아가지 않음.
4. 모든 조항 선택목록의 선생성 제거, 별첨 완료 근거도 최대 하나, 결과 렌더 작업 사이 화면 처리 기회 제공.

## 성능 재현 및 합격 해석

이전 재현과 동일한 2,821자·57분절 조항, 태그 문서 500개×서로 다른 근거 52개(26,000행), 코퍼스 29건을 사용한다. 태그 52열이 항상 근거 52행을 의미하지 않는다. 사용자 자료의 반출은 요구하지 않는다.

v1.89 배포 업데이트와 새 버전을 격리 브라우저에서 비교한다. 페이지 CPU 지연 없음과 4배 지연, 실제 버튼 경로, 화면 타이머 공백·long task·총 시간·취소 응답을 측정한다. Worker 자체의 직접 CPU 지연 설정은 지원되지 않았으므로 전체 계산의 동일한 지연 조건으로 일반화하지 않는다. 총 시간 감소와 화면 응답성은 따로 본다. 기능 보존 확인 없이 빠른 결과만 합격으로 처리하지 않는다.

검색 결과를 기다리는 동안 화면 타이머가 지속되고 취소가 작동해야 한다. 취소 후 부분 판정은 없어야 한다. 대량 참고 검색 준비가 단일 메인 스레드 작업으로 다시 넘어가면 불합격이다. 포스트메시지 자료 복제·UI 렌더 등 잔여 long task는 따로 공개한다. 각 조건의 표본 수·최초/재분석 구분과 실제 폐쇄망 미검증 한계를 기록한다.
