# v1.59.0 — 적재 이력 기반 평가 후보

폐쇄망의 계약검토 이력 DB를 직접 읽습니다. .crhistory 파일을 외부로 보내거나 다시 업로드할 필요가 없습니다. 기존 이력과 판정은 변경하지 않습니다.

## 사용 순서

1. 기존 영구 실행기에서 업데이트합니다. 관리모드의 ‘골드셋 채점’ 탭 → ‘적재 이력으로 평가 후보 만들기’를 엽니다.
2. ‘적재 이력에서 후보 불러오기’를 누릅니다. 제목·부서·유형·태그로 검색하고 후보를 선택합니다. 최신 적재 리비전만 후보로 사용하며 첨부 참조, 의견 존재 여부, 신청·결과 충돌 건수를 표시합니다.
3. 입력 화면에서 그 후보에 해당하는 실제 계약서와 별첨을 불러와 분석합니다. 이력의 첨부파일명만으로 실제 파일이 연결되지는 않습니다.
4. 공통 계약 계열 ID, 계약 기준일, 검토 전/수정 후 버전을 입력합니다. ‘준비 상태 저장’은 현재 브라우저에 이력 리비전별 준비 메타데이터만 저장합니다. 원문·정답의 백업이 아닙니다.
5. 선택 이력과 현재 원문·별첨·버전의 일치를 직접 확인하고 ‘관찰·블라인드 정답 양식 만들기’를 누릅니다. 문서 버전 불명, 미분석, 원문 변경, 연결 대조 미확인은 생성하지 않습니다.
6. 관찰 파일, 정답 파일, 연결 이력 파일 3개가 다운로드되었는지 확인하여 내부 승인 폴더에 보관합니다. 브라우저의 복수 다운로드 차단 여부를 확인하세요.
7. 독립 검수자에게는 정답 파일만 전달합니다. 같은 탭 아래 ‘블라인드 정답 검수’에서 열어 원문을 대조하고 정답을 기록합니다. 두 검수자의 결과를 기존 다계약 시험셋 작업대에서 취합·검증합니다.

## 평가 해석과 제한

- 과거 의견·이상없음 판정·태그를 정답에 복사하지 않습니다. 전체 활성 체크의 정답은 빈값이며, 검수 완료나 자동 승인으로 처리하지 않습니다.
- 이력 기반 후보의 관찰과 재실행은 과거 이력 검색을 전부 제외합니다. 이력·태그 참고로 향상된 성능이 아니라 검색 없는 기준선 평가입니다. 시험셋 누출을 막는 첫 단계이며, 검색 보조 성능의 비교 평가는 별도 기능이 필요합니다.
- 공통 계약 계열 ID와 원문 버전의 정확성은 준비 담당자가 확인해야 합니다. 동일 계열의 다른 계약을 자동 식별하거나 과거 원본 파일을 자동으로 내려받지 않습니다.
- 연결 이력에는 원천 ID·리비전·문서 버전·문서 묶음 지문을 기록합니다. 원천 ID와 과거 의견은 블라인드 정답 파일에 넣지 않습니다. 원문 자체에 포함된 식별정보는 자동 익명화하지 않습니다.
- 기존 자동 승인 설정은 바꾸지 않습니다. 후보 생성은 검증된 평가셋 확보나 자동판정의 안전성 입증과 다릅니다.
