# v1.89 독립 성능·보존 시험

## 측정 범위

동일 합성 입력으로 배포된 v1.88.0 업데이트 파일과 새 v1.89 HTML을 비교한다. 이전 업데이트의 SHA-256과 앱·엔진 버전을 확인한 후 임시 경로에 복원한다. 브라우저는 전용 프로필의 CDP `Target.createBrowserContext`로 매번 저장소를 격리하고, 외부 HTTP·WebSocket 요청을 차단·집계한다. 사용자 계약, 태깅 파일, 기존 브라우저 저장소는 사용하지 않는다.

| 조건 | 고정 입력 |
|---|---|
| 긴 일반 본문 | 1,400개 조문, 71,147자, 서로 다른 조문 내용 14개를 100회 반복 |
| 긴 구조형 본문 | 동일 본문을 2,803개 DOCX 문단 구조 블록으로 구성, 71,148자 |
| 지식 자료 | 합성 태깅 문서 300건, 태그 정의 14개, 합성 코퍼스 100건·수기 판정 400개 |
| 등록 표준 후보 | 현재 요건을 충족하지 않는 과거 연결 40개 뒤에 유효 표준 1개 |
| 저장·입력 부하 | 원문을 가진 합성 과거 패킷 100개, Archive ON, 실제 메모 input/change/blur 및 페이지 새로고침 |

일반 본문·구조형·표준 후보 조건마다 최초 분석 1회와 준비 실행 이후 재분석·화면 렌더 각 10회를 측정한다. 비교 버전 실행 순서는 반복마다 교대로 바꾸되 동시에 실행하지 않는다. `runAnalysis`와 실제 `renderClauses`/`renderReport`를 호출하며 캐시를 위조하거나 평가 함수를 대체하지 않는다. 강제 동기 레이아웃은 포함하고 GPU 페인트 시간은 제외한다. 반복 수가 10 미만이면 P50/P95를 기록하지 않는다.

## 최종 빌드 실측 결과

Chrome 153.0.8010.48, Node v24.14.0, macOS arm64·논리 CPU 10개 환경에서 측정했다. 아래 값은 `v1.88 → v1.89`, 단위는 ms이며 괄호는 P95다. 최초 분석은 1회 값이고 나머지는 각 10회의 P50(P95)다. 중간 빌드·동시 회귀시험과 겹친 중단 실행은 최종 JSON에 포함하지 않았다.

| 조건 | 최초 분석 | 반복 재분석 | 화면 렌더 |
|---|---:|---:|---:|
| 일반 본문 | 7188.8 → 776.7 | 5228.7(6181.8) → 429.5(841.1) | 132.0(160.6) → 107.6(153.1) |
| 구조형 본문 | 7378.0 → 854.2 | 5286.8(6508.3) → 444.1(707.5) | 120.5(163.0) → 101.6(113.6) |
| 과거 연결 표준 40개 + 유효 표준 1개 | 7307.9 → 793.2 | 5280.8(6194.2) → 420.2(463.9) | 138.6(182.5) → 121.4(177.4) |

세 조건 모두 활성 질문 28개, 자동판정 13개(이 합성 입력의 46.4%)가 유지됐다. 모든 자동판정의 조항 배치와 원문 인용 개수·좌표가 전후 일치했다. 카드별 근거 버튼 최댓값은 200개에서 1개로 줄고, 일반·구조형 자동 메모의 최댓값은 6,016자에서 16자로 줄었다. 전체 proof는 삭제하지 않았다. 이 비율은 실제 계약의 자동판정률·정확도가 아니다.

최종 측정 HTML SHA-256은 v1.88 `d4961a36f7adc83ac670a574db504e02a41e1376310bf12daeb3b7fd31e1e1f9`, v1.89 `26ae13ef4e9ddf6c0fd650b2f27cf5dc5475dc661b49d1e816ff9c4c6923c962`다. 두 앱의 정형 엔진 표기는 `standard-auto-v13`, 인식 엔진 표기는 `agreement-judgment-v2`로 확인했다.

최종 HTML의 UI·저장 수용시험 7개도 모두 통과했다. 긴 구조형 본문에 Archive 100개를 적재한 상태에서 메모 input 27회의 처리시간은 P50 0.7ms/P95 1.0ms였다. 패킷 적재 436.0ms, change/blur 이후 로컬 저장 19.3ms, Archive 반영까지 695.3ms는 각각 단일 관측값이다. 마지막 입력 직후 실제 새로고침과 본문 재분석에서도 수기 메모가 유지됐다. 이 수치는 해당 단계의 지연이며, UI 페인트 시간이나 사람의 타자 간격을 측정한 것은 아니다.

## 반드시 보존할 동작

- 이전·신규 버전의 활성 질문 수와 자동판정 ID·근거 위치를 함께 기록한다. 자동판정 ID 및 조항 위치는 비교 전후 같아야 한다.
- 자동 카드마다 근거 열기 버튼은 최대 1개이고, 자동 메모는 짧은 안내 문구다. 긴 원문을 메모에 중복하지 않으며, 전체 증거·원문 인용 좌표는 유지한다.
- 자동판정은 조항별 검토의 두 번째 칼럼에 남는다. 버튼으로 원문을 열어 실제 증거와 같은 인용문이 보이는지 확인한다.
- 표준 후보의 과거 연결만 믿지 않고 유효한 후보를 찾아야 한다. 유효 후보를 비활성화하면 표준 결과 캐시는 무효화되지만 본건의 독립적인 관할 약정 판정은 유지된다.
- Archive를 켠 상태에서 실제 메모 입력은 즉시 메모리 상태에 반영된다. blur/change 시 저장, 재분석 시 수기 판단 보존, 관련 없는 과거 패킷 보존을 확인한다.
- 마지막 입력 직후 별도 저장 호출이나 인위적 unload 이벤트 없이 실제 페이지를 새로고침한다. 새 페이지와 본문 재분석에서 마지막 입력·수기 출처를 확인한다.
- 최상위 UI 경로에서 명사형 태그 별칭 `암호화 ← 비가독화처리`를 연결한다. 별칭 없음은 자동완료가 아니고, 현재 긍정 약정은 자동완료·② 배치, `비가독화처리하지 않으며 저장한다`는 자동완료가 아니어야 한다.

## 결과 파일과 재실행

측정 수치와 원시 표본은 [런타임 비교 JSON](v1.89-runtime-benchmark.json), 기능·저장 보존 결과는 [성능 수용시험 JSON](v1.89-performance-acceptance.json)에 보관한다. 각 결과는 실제 실행한 HTML의 SHA-256, 버전, 합성 입력 규모를 포함한다.

전용 Chrome을 `127.0.0.1:9369`에서 준비한 뒤 순서대로 실행한다. 다른 CPU·브라우저 부하와 중첩 실행하지 않는다.

```sh
CR_OUTPUT=docs/v1.89-runtime-benchmark.json node build/benchmark_v189_runtime.mjs
CR_OUTPUT=docs/v1.89-performance-acceptance.json node build/test_v189_performance.mjs
```

이 시험은 다양한 계약 1,400개나 실제 DOCX 변환 성능의 평가가 아니다. 코퍼스의 기존 결론을 현재 계약의 정답으로 재사용하지 않는다. 숫자는 해당 장비에서의 관측 결과이며 실제 폐쇄망 속도·개선률 또는 법적 정확도를 보장하지 않는다.
