# Python 현재 원문 자동판정 연결

2026-09-21. Python 3.9·FastAPI·분리된 정적 프론트·서버 로컬 SQLite 구성을 유지하여 현재 계약의 자동판정을 서버와 기존 3열 화면에 연결했다. 파일 추출·분석·수기 검토 흐름은 [앞선 작업 기록](2026-09-21-python39-workflow.md)에 이어진다.

## 구현과 저장 경계

- ClauseSemantics의 역할·약어·조항 의미·조건·표·호/목/세목 문맥과 AgreementJudgment의 질문별 요건, 부정·예외·상충·미정, 조/항/호/목 범위 및 별첨 참조를 Python으로 이전했다.
- StandardAuto의 질문 의미 버전·정책·적용 조건을 검사한다. 약정 존재 확인 규칙만 자동 적용하며, 적정성 등 사람의 판단 대상은 직접 검토하도록 남긴다. 실행할 때 기존 JavaScript 엔진, Node, JS 인터프리터를 사용하지 않는다.
- 자동 결과와 문서별 UTF-16 근거 위치는 서버의 분석 레코드에 저장한다. 자동으로 요건을 확인한 항목에는 이상없음/반영되어 있음을 표시한다. 브라우저의 origin=auto 제출은 거절한다.
- 사람의 의견은 자동판정에 우선한다. 변경된 원문에 대한 이전 수기 의견도 삭제하거나 자동으로 대체하지 않고 재확인을 요구한다. 같은 입력 재분석은 수기 의견을 유지한다.
- 입력·첨부·조건·지식 데이터·Python 엔진 해시를 분석 지문에 포함한다. 배포된 엔진이나 현재 입력이 달라지면 예전 분석과 자동 결과를 현재 결과로 사용할 수 없다.
- 완료 시 최신 분석과 대상 의견별 revision, 원본 대조 확인을 검사한다. 자동 근거·수기 의견·원문·첨부·종합 의견을 불변 스냅샷으로 보관한다. 이후 의견 또는 종합 초안 변경은 과거 완료 기록을 바꾸지 않는다.
- 화면에 자동 근거·보류 이유·추가 확인사항을 표시한다. 자동 이상없음을 검토의견으로 바꾸면 기본 사유를 비운다. 완료 리포트에서도 자동 확인의 원문 근거를 펼칠 수 있다.

## 설치 산출물과 남은 범위

현재 소스와 모든 패키지 파일을 비교한 앱 wheel SHA-256:

    42fc4978c330e028ad0bb8be3c99681da306bb5d8f6aa14a3a5c9e42cef4c84f

새 개발 인수 묶음은 .runtime/auto-linux-x86_64/bundle 및 .runtime/auto-linux-aarch64/bundle이다. 이전 workflow 묶음이나 기존 ZIP에는 이 자동판정이 없다. 새 묶음도 실제 Linux에서 실행한 운영 릴리스가 아니다. Python/OS/Nginx와 사내 인증서는 별도로 준비해야 한다.

구형 검토 JSON의 전체 이관, 과거 판단·등록 표준 재사용, 평가·지식 검수·관리·로컬 AI 화면의 전체 연결은 남아 있다. DecisionEvidence의 현재 참조 연결은 이전했지만 과거 판정 재사용을 위한 전체 fingerprint/bundle 인터페이스를 이전했다고 주장하지 않는다. 기존 JavaScript의 WeakMap 티켓은 브라우저에 이식하지 않고 서버 소유 분석과 입력 지문·권한 검사로 대체했다.

Linux 배포판·CPU는 사용자에게 다시 질문하지 않고 preflight로 확인한다. 실제 Linux의 Python·systemd·Nginx·HTTPS·부팅 후 복구 인수검증은 이번 환경에서 실행하지 못했다. 이미지 PDF OCR 및 구형 문서의 복잡한 표·번호 완전 복원도 여전히 지원 범위 밖이다. 전체 앱의 운영 전환 완료로 표시하지 않는다.
