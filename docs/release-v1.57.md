# v1.57 구조 추출·별첨 구역 개선

## 달라진 점

별첨과 본문의 조 번호가 같다는 이유로 중복이라고 판단하지 않도록 문서 구조 모델을 연결했다. 단순히 경고를 숨기는 변경이 아니다. 별첨 표제에 제목·괄호가 붙어도 독립 구역으로 관리하며, 같은 구역의 실제 중복은 계속 검사한다.

- 파일 → 텍스트와 구조 블록 → 본문/별첨/부칙 구역 → 조항 주소 → 인용·중복 검사.
- 별첨 1, [별첨 1] 보안관리약정서, 별첨 1-1, 별표·별지·붙임·부록·Annex 표제 등을 처리한다.
- 같은 이름의 별첨도 위치별 독립 ID를 갖는다. 이름만으로 인용 대상을 확정하지 않는다.
- 본 계약 제2조, 별첨 1 제2조처럼 명시된 대상은 해당 구역에서 찾는다. 다른 구역에서 번호가 하나 발견됐다는 이유만으로 연결하지 않는다.
- 본문 속 별첨 구역과 업로드된 별첨 파일명을 함께 조회한다. 별첨 표제를 ‘없는 별첨 인용’으로 처리하지 않는다.
- 목차 목록·인용 문장은 경계에서 제외한다. 번호 재시작만으로는 구역을 생성하지 않는다.

## 네 형식의 구현 범위

| 형식 | 구현 | 남는 한계 |
|---|---|---|
| DOCX | 자동번호 정의/시작값, 스타일 상속, 번호 수준, 문단/표 셀·텍스트상자, 파트 출처 보존. 변경추적은 삽입 포함·삭제 제외 | 모든 Word 레이아웃·번호 스타일 연결의 완전 재현은 아님. 실제 페이지 번호를 만들어 내지 않음 |
| HWPX | header의 문단 번호 정의와 section 문단 연결, 숫자 템플릿/번호 수준, 중첩 표 셀과 XML 경로 보존 | 복잡한 개요·사용자 기호·재시작 조합은 추가 실자료 검증 필요 |
| HWP | DocInfo 문단 모양/번호 정의 참조, 지원되는 수준별 숫자 템플릿 복원, 섹션/레코드/문단 속성 보존 | 의미를 확정할 수 없는 인라인 자동번호는 임의 조·항 순번으로 만들지 않음. □와 출처 안내로 남김. 구형/암호 문서는 변환 필요 |
| PDF | 페이지·좌표·글자 속성 보존, 좌표 기반 줄과 표제 조각 결합, 큰 가로 간격 분리, 반복 상하단 문구 표시 | 복잡한 다단·표의 읽기 순서/의미를 완전히 해석하지 않음. 스캔 OCR 엔진은 포함하지 않음 |

HWP 문단 헤더·문단 모양·번호 정의의 구현은 [한컴 공개 HWP 5.0 명세](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)의 해당 구조를 참조했다. 이 구현이 한컴 렌더러와 동일한 완전 호환 구현이라는 뜻은 아니다.

## 사용법

1. 원본 파일을 다시 불러와 분석한다. 이전에 추출한 텍스트만 붙여넣으면 원본 파일의 구조·좌표는 복구되지 않는다.
2. 계약서 단위 검토에서 ‘본문·별첨 구역 → 원본 위치 / 경계 보정’을 펼쳐 자동 분리된 구역을 확인한다. 원본 문구와 페이지/문단/레코드 출처를 함께 볼 수 있다.
3. 표제 없는 약정서 등 구분이 어려운 곳은 시작 줄을 선택하고 ‘여기부터 별첨 / 별도 문서’, 구역 이름을 지정한다. 예를 들어 별첨 1 보안관리약정서로 지정하면 뒤의 조 번호 중복과 별첨 존재 검사가 함께 갱신된다.
4. 중첩 문서는 앞에 있는 상위 구역을 선택할 수 있다. 잘못 잡힌 경계는 ‘앞 구역의 연속’으로 보정한다. 보정은 해당 시작 줄에서 해제할 수 있다.
5. 원본을 확인할 수 없는 일부 구역은 다음 구역까지 번호 검사만 제외할 수 있다. 전체 문서나 다른 계약 검토 기능을 끄지 않는다.
6. 보정은 텍스트와 원본 파일 SHA-256 지문을 기준으로 브라우저에 저장된다. 텍스트/파일 변경 시 다른 입력에 이월하지 않는다. 동일 원본과 동일 텍스트를 다시 불러오면 해당 보정을 읽는다.
7. ‘구조·보정 내부 백업’으로 저장하고 같은 원본을 불러온 상태에서 복구한다. 백업에는 원문이 포함되므로 폐쇄망 안에만 보관한다. 파일 지문은 변경 검출용이며 인증/전자서명이 아니다.

기존 사람 판정·과거 이력의 조항 주소를 이 기능이 임의 변경하지 않는다. 매핑용 조항 분할과 구역 검사를 분리했으며, 추출 내용이 바뀐 원본은 기존 자동 완료를 신뢰하지 않는 안전성 흐름을 유지한다.

## 대안과 검증 경계

복잡한 HWP 번호 정의, 텍스트층이 없는 PDF 또는 읽기 순서가 깨진 자료는 폐쇄망의 승인된 원본 프로그램에서 HWPX/텍스트 PDF로 변환하거나 내부 OCR 결과를 원본과 대조해야 한다. 프로그램 설치·라이선스·OCR 구축은 이 배포에 포함하지 않는다. 외부 업로드는 하지 않는다.

합성 DOCX·HWPX·HWP·PDF 원본을 실제 파일 추출 경로로 검증했다. 별첨 중복/누락 오탐 해소, 같은 구역 실제 중복 유지, 경계 보정·백업/복구·입력 변경 무효화를 브라우저에서 시험했다. 실제 폐쇄망 자료의 정확도와 계약당 보정 횟수는 아직 측정하지 않았다.
