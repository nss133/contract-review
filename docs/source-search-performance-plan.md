# 출처·태그 참고 검색 병목과 대안

2026-09-18. 폐쇄망 실제 자료는 반출·측정하지 않았음. 현재 문제를 태깅자료 자체의 문제로 단정하지 않으며, 자료 활용과 중복 계산을 구별함.

후속: 사용자가 1~3 모두 진행을 승인하여 v1.90.3에 참고 검색 분리·재지정 부분 갱신·검색 색인/질의 재사용을 구현함. 아래 제안은 당시 기록으로 보존하며 현재 상태는 [v1.90.3 변경 안내](release-v1.90.3.md)와 [검증 기록](v1.90.3-validation.md)을 우선함. 색인은 실행 중 메모리에 유지하며 자료 변경 시 재구축함. 영구 색인·문서 단위 증분 재구축까지 구현했다는 뜻은 아님.

## 확인된 병목

v1.90.1 Worker를 고정하여 Node에서 합성 계약 2,821자, 체크항목 99개(공통·위탁 모듈을 넓게 활성화), 태깅자료 500건·서로 다른 근거 26,000행·코퍼스 29건으로 측정함. 브라우저 및 폐쇄망 실제 실행시간과 동일하지 않음.

| 작업 | 최초 | 같은 입력 재실행 |
|---|---:|---:|
| 전체 Worker 작업 | 9.022초 | 6.692초 |
| 항목별 태깅 참고 후보 검색 | 7.729초 | 6.546초 |
| 과거 표현 인덱스 준비 | 0.937초 | 0.001초 |
| 원문 패킷·판정 출처 연결 | 0.00024초 | 0.00015초 |
| 문서 완결성 검사 | 0.0024초 | 0.0005초 |

근거: build/profile_source_stage.mjs, CR_PROFILE_BASELINE=1. 시간은 반복 벤치마크의 통계가 아닌 2회 측정값임. 별도 예비 시험의 2,000건·104,000행에서는 최초 36.0초 중 참고 검색 31.5초였으나 다른 시험과 동시에 실행했으므로 규모별 정밀 배율 비교에는 쓰지 않음.

느린 함수는 DecisionReferences.retrieve임. 각 체크항목마다 전체 태깅 문서를 대상으로 태그 비교·문자 벡터 유사도·한글 단어 집합 유사도를 계산하고 정렬함. 문서의 인덱스 일부는 재사용하지만 단어 집합 생성과 질의별 전체 점수 계산을 반복함. 재실행에도 높은 비용이 남음.

이 결과는 현재 앱에서 standardReport의 태깅자료 참고 후보 표시에 사용됨. 이 목록을 현재 약정 충족 근거로 승인하는 경로와는 별개임. 매핑의 HistoryAssist/JudgmentHints와 현재 약정 검사에 공급되는 태그 사전은 별도의 경로이므로 함께 끄면 안 됨. JudgmentSources.compile의 ID·원문 연결 자체가 위 시험의 주범은 아니었음.

## 제안하는 구조 변경 — 이번에는 미구현

1. 핵심 검토와 참고 목록 분리: 매핑·현재 원문 확인·자동판정을 먼저 완료하고, 관리 화면의 과거 참고 목록은 조회할 때 별도 Worker에서 검색함. 불러오기 전 상태를 ‘참고 없음’으로 거짓 표시하지 말고 ‘미조회/검색 중’으로 구분함. 비동기 결과가 도착해도 수기 판정을 바꾸지 않음.
2. 자료 준비를 한 번만: 문서별 단어 집합·벡터·태그별 문서 목록을 적재/변경 시 준비하고, 바뀐 자료만 갱신함. 영구 색인을 쓰는 경우 엔진 버전·동의어 설정·자료 개정 식별자를 함께 보관해 오래된 검색 결과의 재사용을 막음.
3. 관련 후보를 먼저 선택: 체크 ID 직접 연결과 현재 필터의 태그 일치 조건으로 후보를 선택한 후 유사도를 계산함. 기존 필터를 통과할 문서가 빠지지 않는 동등성 시험이 선행되어야 함. 단순히 최근 N건만 잘라 정확도를 낮추지 않음.
4. 편집과 전체 분석 분리: 메모/판정 저장은 저장과 해당 화면만, 조항 재지정은 해당 항목의 연결·관련 판정만 재확인함. 본문·별첨·적용 범위·판정 규칙이 바뀐 경우에는 필요한 재분석을 유지함.

우선순위는 1 → 4 → 2·3임. LLM 도입이나 태깅자료 삭제가 필요한 문제는 아님. 먼저 ‘참고 검색 완료를 기다려야 검토를 시작할 수 있는 구조’를 해소하는 것이 목적임. 이후 같은 입력의 매핑 결과·자동판정·근거·수기 보존이 이전과 같은지, 실제 클릭·타이핑 지연이 줄었는지를 함께 검증해야 함.

## 별도 승인된 변경

완결성 자동점검·경고·완료차단 제외는 v1.90.2의 범위임. 원문 추출·구역/조항 인식·자동판정 원문 검증·기존 사용자 의견은 보존함. 완결성 제외만으로 위 참고 검색 병목이나 사용자 환경의 3분 지연을 해결했다고 주장하지 않음.
