# 안전성 개선 잔여 구현 범위

사용자 승인: “응 계속 해 모두”. 폐쇄망 자료 반출 없이 가능한 구현을 끝까지 연결한다.

1. 출처 한 문장 단위의 과거자료 보강, 주체·긍정/부정·시점 차이 검사, 계열/시점/본건 제외 필터.
2. 선언형 요건 규칙: 주체·행위·대상·조건·수치·금지/의무, 본문과 별첨의 반대근거 및 정보 부족. 규칙 밖의 법적 의미를 확정하지 않는다.
3. 브라우저 내부 블라인드 검수 편집, 독립 2인 결과 대조, 이견의 별도 조정 이력.
4. 다계약 데이터셋 고정·버전 지문·개발/시험/반례 분리·같은 계열과 중복 본문 차단·검색 자료 누수 검증·집단별 지표.
5. 규칙별 승인/만료/중지/재승인/복구 이력, 오류 발생 시 해당 규칙 중지, 전역 중지, 본건 근거 지문 변화 시 기존 시스템 판정 재확인.
6. 실제 앱과 내부 평가에 위 흐름을 연결하고, 단위·반례·브라우저 회귀를 거쳐 배포한다.

자동허용은 내부에서 작성한 좁은 규칙과 원본 품질·적용범위 확인, 두 사람의 검수, 독립 시험의 위험 한도, 실제 근거가 함께 충족되는 경우만 고려한다. 초기 규칙 목록과 승인 목록은 비어 있다. 임의의 법적 정답·승인·실자료 성능을 생성하지 않는다. 승인되지 않은 규칙은 관찰만 한다.

폐쇄망 내부 검수자의 업무(실제 라벨 확정·규칙의 법적 충분성 승인·위험 한도 승인)는 개발 완료와 별개다. 클라이언트 단일 HTML의 이름 입력은 조직 인증/전자서명이 아니므로 내부 접근통제와 승인 문서가 필요하다.

## 구현·검증 결과

위 1~6의 로컬 소프트웨어 흐름을 v1.55.0에 연결했다. Node 477건·Python 103건 통과. 합성 브라우저 시험에서 블라인드 검수, 전체 계약 재실행, 고정 시험, 규칙 승인과 별도 활성화, 실제 자동판정 적용, 원문 변경 즉시 회수, 규칙 중지, 비활성 복구를 확인했다. 시험의 60개 계열은 합성자료로 기능 확인용이며 성능 근거가 아니다.

사용 절차와 한계는 [안전성 작업대 안내](safe-auto-verdict-v1.55.md)를 따른다. 체크 전체의 법적 충분성 규칙을 임의로 만들어 채우지 않았고 초기 규칙·승인은 비어 있다. 실자료 검수·법무 승인·폐쇄망 설치는 미수행이다.
