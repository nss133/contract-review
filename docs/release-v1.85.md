# v1.85.0 — 중첩 번호 목록과 항·호·목 참조 연결

## 이번에 완료한 개발

①항 아래 1호가 있고 그 안에 가목·나목이 있는 약정을 읽도록 보강했습니다. 명시된 상위 문장의 주체·의무와 지원하는 조건을 하위 항목에 연결해 직접 판정, 등록 표준 비교, 원문으로 확인된 사용자 판단 재사용에 반영합니다. 항목마다 주체가 반복되어야 하는 제약을 줄였습니다.

- 같은 파일·명시 별첨 구역·조·항 안의 호→목 두 단계를 지원합니다. 호는 1. / 1) / (1), 목은 가. / 가) / (가) 방식이며, 각 단계에서 번호가 연속되고 표기가 일관되어야 합니다. 상위에 ‘다음/아래 각 호·목의 사항·의무를 이행·준수한다’ 또는 지원하는 금지 도입문이 있어야 합니다.
- 신탁계약 변경 시 통지처럼 이미 지원하던 9종 조건을 도입문에 쓴 경우 하위 의무에 전달합니다. 알 수 없는 조건, ‘경우에만’이라는 추가 한정, 서로 다른 조건이나 주체를 임의로 합치지 않습니다. 목록 전체가 지원하는 약정 요소로 해석되어야 합니다.
- ‘제1조 제2항 제1호 가목’처럼 명시된 경로를 연결합니다. 같은 조에서 ①항과 ②항이 각각 1호부터 시작해도 구별합니다. 현재 항의 호 참조도 처리하며, 항 없이 여러 1호 중 하나를 선택하지 않습니다. 다른 조에서 해당 항목을 제한하는 문장도 비교합니다.
- 원문에서 ‘다.’ 목 번호가 문장 종결로 잘리는 문제를 수정했습니다. 단순 줄바꿈 복원도 호·목 경계를 넘지 않습니다. 번호가 이미 사라진 추출물을 추정 복원하는 기능은 아닙니다.
- 판정 근거에는 상위 도입문부터 호·목 원문까지 표시합니다. 내부 비교용으로 확장한 문장을 원문처럼 표시하지 않습니다. 참조 대상의 항 번호나 호·목 경로가 바뀌면 본문이 같아도 과거 근거와 구분합니다.

질문의 범위는 직접 규칙 64개·관련 조항 이력 재사용 66개로 유지합니다. 이 수치는 모든 문구의 인식률이나 실계약 자동판정률이 아닙니다. 실제 교육·점검·신고 등의 이행 여부를 확인하지 않으며, 태그 유사도만으로 적정성을 승인하지 않습니다.

## 저장자료·화면

기존 자동등록 표준은 연결 규칙 13으로 재승인 없이 갱신합니다. 이전 규칙 12에서 중첩 약정이 연결되지 않았던 자료도 자동으로 다시 처리합니다. 수동 설정과 사용 중지 상태는 유지합니다.

자동 이상없음은 기존 조항별 검토의 ② 확인 완료에 반영합니다. 원문·번호·조건·주체·참조가 바뀌면 자동판정을 다시 검사하고, 사용자가 직접 남긴 판정은 덮어쓰지 않습니다. 별도 검토 화면이나 자료 승인 절차는 추가하지 않았습니다.

## 검증

Node 990개·Python 106개, 총 1,096개 회귀시험과 배포 HTML의 브라우저 15개 흐름을 통과했습니다. 신규 단위시험 40개에 중첩 목록의 직접 판정·표준 양방향 비교·사람 판정 재사용·최신 정정·원문 보존·참조 변경·잘못된 번호와 조건 차단을 포함했습니다.

배포 HTML에서 23종 질문의 합성 중첩 문구를 검사했습니다. 그중 인력관리·라이선스·개인정보 교육감독·질권 통지협력·기업결합 신고 협조 5종은 실제 분석 화면에서 자동판정과 ②열 이동을 확인했습니다. 별첨 단독 근거, 상위 도입문 전체 표시, 번호·조건·주체 변경 시 철회, 사람 판정 보존, 표준 자동등록과 규칙 12→13 갱신, 항·호·목 참조를 포함한 사람 판정 재사용·변경 시 철회를 검증했습니다. 기존 단일 목록·보안·표준·코퍼스·완료·실제 PDF 등록 흐름도 통과했습니다. 시험한 앱 흐름에 런타임 오류와 외부 통신은 없었습니다.

기존 보안관리약정서 3종에 무관한 조항을 추가한 표준 비교는 3·6·6개로 유지됐습니다. 공개 자료 5종의 직접 자동충족은 계속 0개였습니다. 이는 제한된 개발 시험이며, 폐쇄망 실자료의 자동판정률·오판율 변화를 실측한 것은 아닙니다.
