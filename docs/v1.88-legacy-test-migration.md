# v1.88 기존 시험 기대값 이관 점검

2026-09-18. 최초에는 승인된 기준 재정의 실행계획에 명시된 변경만 식별한 제한시간 점검으로 작성함. 이후 아래 6절의 9개 시험 파일에 이관을 적용함. 제품 코드는 이 작업에서 수정하지 않았으며 기존 시험 전체의 이관 완료를 뜻하지 않음.

## 1. 판정 원칙

시험 실패는 먼저 정책 변경과 실제 결함으로 나눔. 현재 엔진이 내놓은 값으로 기대값을 일괄 치환하거나, 파일 전체를 건너뛰어 통과 수를 높이지 않음. 한 시험에 폐기한 조건과 유지해야 할 안전조건이 섞였으면 시험을 분리함.

특히 ‘질문 문자열 변경’은 두 종류로 나눠야 함. 설명만 다르고 의미가 같은 변경은 판정 유지 대상이지만, 약정 존재 질문을 유불리·교육 등 새 의무까지 묻는 질문으로 바꾼 것은 의미 변경임. 같은 ID라고 새 의미에 옛 자동 이상없음을 이식하는 시험으로 바꾸면 안 됨.

## 3. 그대로 유지해야 하는 안전·상태 회귀

다음 실패는 ‘정책이 바뀌었다’는 이유로 통과 기대나 skip으로 바꾸면 안 됨.

1. 제목·목차·작성예시·태그에만 쟁점이 있는데 본건 약정으로 자동 통과하는 경우. tests/v188_acceptance.test.js에 직접·표준 등록·적용 경로 반례가 있음.
2. 같은 질문의 명시적 반대 약정, 동일 대가의 VAT/금액 충돌, 불가능·역전 날짜, 미정·공란, 지목한 적용 별첨 미확인. 질문별 최소요건과 연결해 유지함.
3. 현재 문서에 없는 인용을 근거로 저장하는 경우, 표준 등록 여부만으로 본건 적용을 만들어내는 경우, 자동 판정을 사람 정답으로 승격하는 경우.
4. 위조·재사용 티켓 거부와 기존 수기 판정 보호. tests/standard_auto.test.js, tests/template_library.test.js, tests/verdict.test.js, tests/auto_safety.test.js의 관련 보증을 새 공통 경로에서도 유지함.
5. 제1조 재시작의 본문/별첨 구역 구별, 표 셀/원문 위치, 조문 참조 대상과 범위·순환 구조 보존. tests/obligation_lists.test.js, tests/nested_obligation_lists.test.js, tests/table_obligations.test.js, tests/security_reference_expansion.test.js의 순수 추출·주소·해석기 시험은 자동판정 게이트 변화만으로 폐기하지 않음.
6. 구문 분석기의 parse/key가 서로 다른 조건을 구별하는 사실은 유지함. 옛 parser가 해석하지 못하면 새 공통 판정도 반드시 실패해야 한다는 결합만 해제함.
7. 같은 의미의 표시 변경·무관한 DB 추가로 수기 판정을 잃지 않음. 반대로 실제 관련 원문 변경·질문 의미 확장·동시 수기 충돌을 무시하여 완료를 만들지 않음. tests/review_completion.test.js 및 새 tests/v188_lifecycle.test.js와 함께 확인함.
8. 자동 완료가 ②열에 표시되고 보고서·저장·검토 마치기의 미결 분모가 일치함. 제외·통합된 구 ID가 숨은 완료 차단을 만들지 않음.
9. 외부 요청 0, 개인 원문 미내장, 기존 데이터 복구 가능성. 시험 편의를 위해 추출기 결과를 가짜로 바꾼 것을 4형식 실제 파일 통과라고 주장하지 않음.

## 5. 작업·보고 방법

각 수정은 구 기대·승인계획 근거·새 기대·대응 반례를 함께 남김. 이 문서는 점검한 범주와 파일 목록이지 자동변경 지시서가 아님. 모호한 적정성·유불리 조건을 추가로 완화해야 하는 실패는 전수 기준표의 결정 근거 없이 수정하지 않음.

최종 결과는 유지한 기존 회귀, 정책 변경으로 대체한 회귀, 새 수용시험, 미실행/제외를 나눠 집계함. 이전 총시험 수보다 줄었다는 이유만으로 실패로 보지도 않고, 줄인 후 통과했다는 이유만으로 전체 개발 완료를 주장하지도 않음.

## 6. 실제 이관 적용 기록

담당 9개 파일에서 실행되는 시험 수는 이관 전후 모두 114개임. 파일·시험 단위 skip을 추가하지 않았음. 이전 판정이 아니라 위 승인된 정책 변경을 근거로 ID·질문 의미·분모·경로 기대를 수정함. 다른 파일의 기준 변경은 담당자가 별도로 관리함.

파일별 유지된 실행 단위는 standard_auto 8, standard_expansion 8, agreement_evidence 8, checklist_content 6, remaining_auto 15, template_library 16, template_register 11, registered_presence 12, template_expansion 30개임. 수정 파일은 9개이고 내부 assertion은 일부 대체·추가하였으므로 ‘114개 기대값을 전부 뒤집었다’는 의미가 아님.

표준 입력란 단위검사는 값의 치환·역할 키·중복 후보 제거를 직접 검사함. 일반적인 상호/날짜 표시란 자체를 개인정보 의무의 추가 충족요건으로 만들지 않음. 그러나 상호가 본문 의무주체에 재사용된 경우의 불일치는 관련성 있는 안전 반례로 남김.

CMN-19의 법원 지정 후 다른 법원도 선택할 수 있다는 문구는 전속관할을 요구하지 않는 현행 기준에 따라 통과로 이관함. CMN-05의 현재 부가세 포함 표시 후 장래 변경 가능성도 현재 미정·모순과 구분함. 대신 각각 ‘위 지정/포함 조건은 적용하지 않으며 추후 정한다’는 실제 현행 약정 배제 반례를 추가하여, 예외 문구를 모두 통과시키는 식으로 약화하지 않음.

CORE-14는 감독기관 협조 약정의 존재를 묻는 현재 범위에서 ‘위탁자’라는 주체 표시만으로 일괄 보류하지 않도록 확정하여 양성으로 이관함. 검사·자료제출에 응하지 않는 명시적 반대 특약은 음성으로 유지함. PRIV-06에서 갑·을의 실제 지위가 정의되지 않았으면 ‘갑’이 곧 위탁자라고 추정하지 않음. 대신 본건에서 위탁자=갑, 수탁자=을을 직접 정의한 뒤 보호의무를 위탁자로 뒤집는 반례를 추가하여 알려진 주체의 충돌은 계속 차단함.
