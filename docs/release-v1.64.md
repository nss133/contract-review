# v1.64.0 — 실사용 매칭 연결·승인용 시험셋·오판 재검수

## 이번에 완료한 개발 연결

- 실제 계약 검토와 평가가 같은 매칭·실제 별첨 검색 코드를 사용합니다. 유형·당사 역할·모듈·원계약 비교 조건을 고정하여 평가하며 현재 계약 판정·화면 상태는 바꾸지 않습니다.
- 독립 검수에 실사용 설정을 연결하고, 다계약 평가묶음을 재실행해 승인 작업대 형식으로 저장·전달합니다. 관찰·정답 파일을 따로 다운로드해서 다시 올릴 필요가 없습니다.
- 오판 의심 신고로 규칙을 중지한 뒤 현재 원문과 신고 내용을 평가자료의 미확정 후보로 편입합니다. 시스템 판정은 정답에 복사하지 않습니다.
- 해당 신고가 반례 시험셋에 포함되고 독립 검수가 완료되기 전에는 규칙 재승인을 차단합니다. 단순히 시험셋 이름이나 규칙 버전만 바꾸는 것으로 신고 사례 편입을 생략할 수 없습니다.

## 사용 순서

1. ‘검토 정확도 평가’에서 원문·초안을 확인하고 독립 검수 2명을 완료합니다. 이번부터 독립 검수 화면에 충족 기준·검토 기준·참고 근거도 표시합니다. 이 기준을 표시하지 않았던 구버전 검수는 새 평가 대상으로 고정하고 다시 검수해야 승인용 연결이 가능합니다. 원래 검수는 보존합니다.
2. 입력 화면에서 같은 계약의 본문·원계약·별첨을 분석하고 유형·당사 역할·모듈을 확인합니다.
3. 평가 화면의 해당 독립 검수를 선택하고 ‘실사용 분석 연결·승인용 시험셋’을 엽니다. 연결 확인자와 원문·범위 확인을 입력하고 실사용 설정 연결을 누릅니다. 문서 묶음·본문 조항 위치·검수 기준이 다르면 연결하지 않습니다.
4. 다른 계약에도 같은 절차를 적용합니다. 기존 다계약 화면에서 개발·분리 시험·반례와 참고자료 계열·검토일을 확인하여 평가묶음을 고정합니다.
5. ‘저장된 평가묶음·승인용 시험셋 불러오기’ → 대상 선택 → ‘실사용 매칭으로 재실행·시험셋 저장’을 누릅니다. 이 재실행은 시험 계열·시점이 격리된 두 종류의 참고자료를 사용합니다.
6. ‘파일 없이 승인 작업대에 전달’을 누릅니다. 작업대의 기존 작업이 있으면 덮어쓰지 않으므로 먼저 내부 저장하고 새로고침한 뒤 전달하세요. 승인 작업대에서 규칙 평가·허용 범위·위험 한도·승인·활성화를 별도로 진행합니다.

전달은 자동승인이나 충분한 표본 수의 보장이 아닙니다. 선정 체크에 대한 독립 정답만 옮기며, 검수하지 않은 체크를 안전 정답으로 채우지 않습니다. 승인 규칙의 체크가 모든 시험 계약에 검수되어 있지 않으면 평가·승인이 보류됩니다.

## 오판 의심 신고

‘자동 이상없음 후보 시험·운영 중지’에서 신고하면 중지가 먼저 저장됩니다. 분석 원문이 있으면 ‘오판 재검수’ 후보를 평가자료 목록에 추가합니다. 문서 버전·원문 확인과 독립 검수는 새로 해야 합니다. 이 후보를 평가묶음에 넣을 때에는 반례로 분류하세요.

신고 당시 원문·판정 기록은 내부 평가 저장소에 보존합니다. 저장 용량 등으로 후보 편입이 실패해도 규칙 중지는 유지됩니다. 실사용 연결 화면의 미편입 신고 목록을 불러와 같은 본문·원계약·별첨으로 다시 시도할 수 있습니다. 원문 지문이 다른 자료는 재시도 편입을 막습니다. 분석 원문이 없거나 구버전 신고에 원문 지문이 없으면 자동 편입을 보장하지 않습니다.

원래 신고·두 검수·제3자 조정 이력은 보존합니다. 사람 판정은 중지 과정에서 지우지 않습니다. 백업에는 승인용 시험셋과 신고 원문도 포함되므로 폐쇄망 내부에만 보관하세요.

## 계획 완료 여부와 한계

이번까지 평가 준비 → 독립 검수·이견 조정 → 자료별 비교 → 실사용 설정 연결 → 승인용 시험셋 전달 → 오판 재검수 편입의 개발 연결을 마련했습니다.

다만 다음을 전체 완료나 정확도 보장으로 표현할 수는 없습니다.

- 실제 폐쇄망 자료로 평가를 실행하고 오류 유형에 따라 매핑 규칙을 정교화하는 작업
- 대표성 있는 충분한 독립 계약 표본과 반례로 위험 한도를 확인하고 자동판정 허용 범위를 내부 승인하는 작업
- 모든 실사용 기능의 종단간 검증: 이번 연결은 매칭·원계약·별첨 검색과 승인 요건에 관한 것으로, 문서 추출 정확도, 사람 재지정, 추가확인 처리, 최종 완료 화면까지의 자동 채점은 포함하지 않습니다.
- 검수자 이름과 자체 무결성 지문은 조직 인증·전자서명·실제 독립성 증명이 아닙니다. 내부 권한 관리와 검수자 분리 절차가 필요합니다.

새 승인 규칙이나 자동허용 범위를 배포하지 않습니다. 개발 테스트 통과를 실자료의 정확도 향상으로 해석하지 마세요.
