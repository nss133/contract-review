# v1.60.0 — 평가자료 자동 준비·과거 판단 기반 초안 (1차)

## 시작

관리모드 없이 ‘검토 정확도 평가’ 탭 → ‘평가자료 준비’를 누릅니다. 기존 계약검토 이력과 법률검토 태깅자료를 읽어 작업 목록을 만듭니다. ID를 직접 입력하지 않습니다. 기존 계약 검토 화면·저장 판정·자동승인 정책은 변경하지 않습니다.

1. 확인할 자료를 고릅니다. 제목·부서·태그로 검색할 수 있습니다.
2. 왼쪽에서 과거 의견과 태그 근거를 보고, 필요한 계약서·별첨을 여러 개 추가합니다. 실제 본문 파일을 지정합니다. 파일명만으로 본문을 확정하지 않습니다.
3. 검토 전/수정 후 문서 버전을 확인합니다. 오른쪽에서 쟁점별 초안과 대응 체크 후보를 확인합니다.
4. 현재 연결한 원문 기준 판단, 근거 위치·이유·확인자를 입력하여 ‘이 판단 확인·저장’을 누릅니다. 대응 체크가 없으면 ‘기존 체크에 없는 쟁점’을 선택합니다. 자료 부족은 보류로 저장할 수 있습니다.
5. 입력 내용은 자동 저장되며 새로 열어도 이어서 작업합니다. 별도 ‘작업 내부 백업’은 계약 원문·과거 의견을 포함하므로 내부에만 보관합니다. 추가 복구는 같은 원천의 기존 로컬 작업을 덮어쓰지 않으며 복구된 판단은 재확인 대상으로 읽습니다.

## 구현 범위

- 명시적인 원천 연결 ID가 같은 계약 이력과 태깅자료만 묶습니다. 비슷한 제목을 근거로 서로 다른 계약을 병합하지 않습니다.
- 최신 원천 리비전을 준비 목록에 사용하고, 변경 전 리비전의 작업도 저장소에 보존합니다.
- 과거 검토결과를 문장·행 단위로 나누어 출처·인용문과 함께 보존합니다. ‘수정 필요’·‘이상없음’ 등 명시 표현으로 판단 후보를 제안하되 조건·부정·예외 문맥은 보수적으로 보류합니다. 이는 일반적인 법률 문맥 이해나 확정 정답 추출을 보장하지 않는 규칙 기반 초안입니다.
- 태그 근거 문장과 과거 검토결론은 구분합니다. 검토결론 원문이 없는 자료는 태그만으로 정답을 만들지 않습니다. 일반 법률검토의 확인은 ‘참고 기준 확인’이며 특정 계약의 정답으로 자동 승격하지 않습니다.
- 원문 파일·본문 지정·문서 버전 변경 시 기존 초안을 재확인으로 돌립니다. 스캔 OCR·추출 실패 문서는 기존 추출기의 한계를 따릅니다.

## 후속 단계 — 이번 배포에 미포함

이 배포는 정답 초안 준비와 담당자 확인까지입니다. 과거 결론을 본 담당자의 확인은 독립 검수로 기록하지 않습니다. 독립 검수·시험셋 확정·매핑/자동판정 채점 연결, 자료별 효과 비교, 자동판정 확대는 후속 단계입니다.

계열 ID는 화면에서 제거했지만 갱신·동일 서식의 계열 추정·확정은 아직 구현하지 않았습니다. 현재 내부 ID는 작업 식별자이며 시험 분리용 계열 확정값이 아닙니다. 원문 일괄 추가는 현재 선택한 자료에 연결되며 여러 계약에 대한 자동 파일 배분, 기존 아카이브 자동 재사용, 복잡한 의견의 의미 단위 추출은 후속 과제입니다.

후보 수·초안 확인 건수는 정확도나 안전성 입증 수치가 아닙니다. 실제 폐쇄망 평가 결과 없이 자동판정 범위를 확대하지 않습니다.
