# v1.87.0 — 자동판정 확대 1~4 통합

요청한 표 연결, 정형 표현 확대, 복합 참조, 조건·예외 범위 구분을 순서대로 구현했습니다. 별도 검토 공간이나 추가 승인 절차 없이 기존 조항별 검토에 적용합니다. 자동 이상없음은 ② 확인 완료에 표시하고, 사람이 남긴 판정은 덮어쓰지 않습니다.

## 1. 표에 나뉜 약정 연결

HWP·HWPX·DOCX의 표 식별자·행·열·병합 정보를, PDF의 명시 열 머리글·좌표를 보존합니다. ‘주체/의무자/의무주체’, ‘대상/대상정보’, ‘의무/의무내용/약정내용’, ‘조건/적용조건’ 열이 명확한 표에서 행 전체를 하나의 약정으로 읽습니다. 머리글 순서가 바뀌어도 열의 의미로 연결하며 판정 근거에는 합성 문장이 아니라 원래 머리글·셀을 표시합니다. 셀 안에서 주체·대상을 반복한 완전 문장은 일치 여부를 확인하고, 서로 다른 주체는 합치지 않습니다.

본문·원계약·별첨·등록 표준·내부 원문 평가자료에 구조를 전달합니다. 표준의 상호·체결일 등 허용 입력란을 채워 본건 별첨으로 쓰는 경우도 표 구조를 유지합니다. 원문이나 좌표가 변경되면 재검사하며, 텍스트와 맞지 않는 좌표는 사용하지 않습니다.

표 전체의 필요한 셀이 해석되어야 합니다. 병합·누락·빈칸·중복 좌표·모르는 열을 임의로 채우지 않습니다. DOCX의 앞·뒤 생략 셀 때문에 뒤의 내용이 다른 열로 밀려 읽히지 않도록 검사합니다. PDF는 텍스트층과 명확한 열 배치가 있어야 하며, 줄바꿈·병합으로 관계가 불확실한 표나 스캔 이미지에 OCR 추정을 추가한 것은 아닙니다.

## 2. 정형 문구와 연속 문장

의무 종결형, 일부 정형 동사와 목적어·주체의 어순 차이를 같은 약정 요소로 읽습니다. 같은 조·항의 ‘또한/아울러’ 뒤에는 직전 문장에서 명확하게 확인된 단일 주체를 연결하고, ‘위 개인정보’ 등은 직전 대상과 일치할 때만 연결합니다. 조건·다른 주체·새 조·항·별첨의 경계는 넘지 않습니다.

구조화한 사실과 태그를 직접 요건 판정, 등록 표준 비교, 원문으로 확인된 사람 판단 재사용에 공통 적용합니다. 부정·재량·노력 의무·수치·조건은 삭제하지 않으며 태그나 유사도 점수만으로 이상없음을 만들지 않습니다.

## 3. 가지번호·복합 경로·3단계 목록

제1조의2 등 가지번호를 포함한 조 범위, ‘제1조 제1항부터 제2조 제2항까지’처럼 서로 다른 부모를 잇는 범위, 호→목→괄호 숫자의 3단계 목록과 명시 세목 참조를 지원합니다. 부모가 생략된 끝 경로는 명시된 공통 부모 안에서만 연결합니다.

양 끝뿐 아니라 중간 조·항과 목록의 연속성·유일성·순서를 확인합니다. 중간 내용·조건·참조 범위가 달라지면 표준·사람 판정과 다르게 비교하며, 다른 조에서 해당 범위를 제한하는 문구도 포함합니다. 외부 법령 번호를 계약 번호로 대체하거나 빠진 번호를 추정하지 않습니다.

## 4. 여러 문장·별첨의 조건과 예외

지원하는 조건이 명시된 도입문과 후속 의무를 결합하고, 기존에 인식하던 신용정보 재위탁 금지의 금융위원회 인정 예외가 두 문장으로 나뉜 경우도 같은 조건으로 읽습니다. 예외가 없던 약정과 예외가 있는 약정은 구분합니다.

‘다만’ 뒤에서 다른 의무만 제한한다는 점이 완전히 해석되면 해당 체크의 보류에서 분리합니다. 예컨대 점검 의무의 명시적 제한은 보호조치 체크를 무조건 막지 않지만, 점검 체크 자체는 통과시키지 않습니다. ‘그 의무’, 모든 의무 면제, 우선적용 등 적용 대상이 불명확하거나 전체를 바꾸는 문구는 유지합니다.

별첨의 조건도 동일하게 읽습니다. 문서 제목·번호로 지목한 다른 별첨의 조건은 참조 원문까지 연결하여 등록 표준 또는 확인된 사람 판단과 비교하고, 조건 변경·별첨 삭제 시 재사용을 철회합니다. 임의의 조건 간 법적 우열을 새로 추론하는 기능은 아닙니다.

## 설치와 기존 자료

기존 실행기의 ‘버전 설치·업데이트’에서 contract-review-v1.87.0.crupdate를 선택한 뒤 재분석하십시오. 실행기 위치·이름과 브라우저 프로필을 유지하고 내부 백업을 보관하십시오.

기존 자동등록 표준은 규칙 15로 재승인 없이 갱신합니다. 수동 설정과 사용 중지 상태는 보존합니다. 단, 구버전에서 표 좌표 없이 평문만 저장한 자료는 좌표를 복원할 수 없습니다. 그런 자료의 표 연결 기능을 쓰려면 폐쇄망 안의 원본 파일을 한 번 다시 불러오거나 등록하면 됩니다. 원문 반출은 필요하지 않습니다.

## 검증 기록

Node 1,045개·Python 106개, 총 1,151개의 회귀시험을 통과했습니다. 기존 표준 3종에 무관한 내용을 추가한 비교에서 충족 항목은 이전과 같은 3·6·6개이며, 공개 자료 5종의 직접 충족은 0개로 유지됐습니다.

신규 지원 기능에 맞춰 선정한 합성 사례 17개를 v1.86과 비교한 결과, 이전에는 0개·이번에는 17개가 자동판정됐습니다. 표 2개, 표현 9개, 참조·3단계 목록 3개, 조건·예외 3개입니다. 각각 주체·조건·번호를 바꾼 반례 17개는 모두 통과하지 못했습니다. 원문·적용 조건을 지정한 개발용 사례이며, 무작위 평가셋이나 실계약의 자동판정률·오판율을 뜻하지 않습니다.

최종 배포 HTML의 브라우저 시험 18개 흐름을 통과했습니다. 실제 형식의 합성 HWP·HWPX·DOCX·PDF 파일 입력부터 자동판정·②열 이동, 표준 등록·갱신, 내부 원문 자료의 표 구조 보존, 출처 변경 시 자동판정 철회와 수동판정 보존을 확인했습니다. 화면 폭 4종에서 완료 열의 넘침이 없으며 시험 중 앱 오류와 외부 요청은 없었습니다.

배포 검사는 브라우저에서 시험한 HTML의 SHA-256과 ZIP의 직접 실행본·비상 실행본·업데이트 본문을 대조합니다. 전체 JavaScript 모듈 82개·CSS의 소스 일치, 업데이트 해시, ZIP 무결성, 최신 사용안내·판정 정책, 사용자 코퍼스 미내장도 검사합니다.

직접 판정 64개·관련 조항 이력 재사용 66개의 질문 범위는 유지하며, 이번 개발은 그 질문들이 읽을 수 있는 문서 구조와 표현을 넓힙니다. 내부 표준 원문과 사용자 코퍼스는 배포본에 내장하지 않으며 외부 AI·네트워크 호출은 추가하지 않았습니다. 실제 폐쇄망 자동판정률·오판율의 변화는 아직 실측하지 않았습니다.
