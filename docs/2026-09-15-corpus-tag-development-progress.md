# 코퍼스·판단태깅 개발 진행 기록

## v1.65 통합 배포

- 본문 매핑이 verify·consider·base_covered여도 승인 규칙의 전체 요건이 실제 문서 묶음에서 확인되면 그 매핑 상태만으로 추가 보류하지 않도록 연결함. 미선정·비적용·재지정·미확인 입력·예외·충돌 차단은 유지함.
- 신규 자동승인 규칙은 생성하거나 활성화하지 않음. 승인 규칙이 없는 환경에서 자동판정률이 즉시 증가한다고 약속하지 않음.
- JavaScript 568개, Python 103개 통과. 배포 HTML에서 간편 비교·구 판정 연결 및 독립 검수·60계열 승인 시뮬레이션·실제 자동판정·원문 변경 시 회수·오판 중지·비활성 복구를 확인함. 승인 경로 브라우저 시험의 외부 요청은 0건임.
- 합성자료 1,000건 검색: 사전 계산 전 p50 1.069ms / p95 1.418ms, 적용 후 p50 0.179ms / p95 0.246ms. 색인 생성 3.887ms. 합성 100건 코퍼스 수정 p50 6.842ms / p95 6.996ms. Node v24.14.0의 로컬 측정이며 폐쇄망 실사용 성능을 보장하지 않음.
- v1.65.0 ZIP·업데이트 해시·버전·사용안내 포함 여부 및 내장 코퍼스 없음 확인. 기존 ZIP은 보존함.
- Word 생성·렌더링 의존 환경을 사용할 수 없어 이번 배포에서는 DOCX를 생성·포함하지 않고 설치 TXT와 변경 사용안내 Markdown을 제공함.
- 범위가 불명확한 예외까지 모두 자동 분리하는 기능, 집계만 남은 자료의 개별 근거 복원, 실제 폐쇄망 자료에서의 자동판정률·오판률 검증은 미완료임. 이 배포를 전체 계획 완료로 표현하지 않음.

## 네 번째 구현 범위

- 평가 첫 화면은 누적 점검·현재 계약 비교를 중심으로 두고 복잡한 정답 작성·독립 검수·승인 시험은 고급 평가로 접음.
- 예전 개별 판정 JSON을 현재 분석한 계약에 연결하는 파일 선택·확인 절차를 추가함. 계약 해시가 다르거나 집계 백업이면 연결하지 않음.
- 사용자가 동일 본문·별첨 버전 및 사람 판정의 재사용 가능성을 확인한 구 기록은 비교용 원문 지문을 추가함. 원래 기록과 연결 확인자·사유·날짜를 보존함.
- 구 출처 미상 판정은 명시적인 연결 확인 후에만 비교 라벨로 사용하며 시스템 판정은 제외함. 과거 조항 번호는 현재 매핑 정답으로 승격하지 않음.
- 이미 원문이 연결된 기록에 다른 버전을 덮어 연결하거나 상충 파일을 임의 선택하지 않음. 저장 실패 시 코퍼스 메모리만 성공 상태로 바뀌지 않도록 함.
- 이 기능은 개별 판정파일이 남아 있을 때의 복원 경로임. 29건 집계 JSON에 없는 계약별 판정·근거를 복구했다고 주장하지 않음.
- JavaScript 566개 통과. 임시 빌드는 저장소 법령 스냅샷만 사용했으며 일부 투자 체크의 원문 미발견 경고가 있어 배포본으로 사용하지 않음. 기존 dist·ZIP은 변경하지 않음.

## 세 번째 구현 범위

- 신규 누적저장·판정 내보내기에 본문·원계약·별첨 묶음, 검토 맥락, 조항 분할, 체크 기준의 지문을 보존함. 원문 자체는 비교용 지문에 복제하지 않음.
- 현재 계약을 과거 판정과 비교하는 버튼을 추가함. 같은 원문 묶음·검토 조건의 사람 판정을 사용하여 실제 매칭 엔진을 참고 전·후로 실행함. 판정과 기존 분석 상태는 변경하지 않음.
- 명시적으로 확인한 근거 조항만 매핑 정답에 포함함. 단순 이상없음 선택, 바뀐 체크, 재확인 필요 판정, 조항분할 변경을 구분함.
- 별첨·맥락 불일치, 집계만 있는 구자료, 상충 파일은 임의로 개별 계약 정답에 연결하지 않음. 이 비교는 독립 시험이나 자동판정률 측정이 아님.
- 명시적 지시어로 바로 이어진 두 문장의 요건을 결합함. 예: 해지 통지 의무 뒤의 ‘이 통지는 서면으로 하여야 한다’. 서로 다른 문서·중간 조항을 넘어 문장을 합치지 않음. 면제·선택·조건부 문장이 있으면 통과시키지 않음.
- 본문과 별첨이 서로 다른 필수 요건을 각각 충족하는 경우와 특약 충돌을 회귀시험으로 확인함. 문서 간 임의의 문장 결합은 하지 않음.
- 코퍼스 변경을 자동승인 엔진 지문에 포함함. 사람 판정의 맥락 지문과는 분리함.
- 임시 HTML만 만드는 빌드 옵션과 브라우저 시험 스크립트를 추가함. 사용자 코퍼스 없는 임시 빌드에서 태그 저장·누적 점검·실제 비교·판정 불변·별첨 불일치 차단·승인 지문 변경을 확인함.
- JavaScript 562개 통과. 구 배포 ZIP은 아직 갱신하지 않음. 관련 예외의 범위 해석 확장, 구 코퍼스 연결 복원, 전체 평가 사용성·성능 검증과 통합 배포는 남아 있음.

## 두 번째 구현 범위

- 사용자 작성 코퍼스 의견을 기존 계약·법률검토 검색 자료에 연결함. 명시적 검토 ID가 일치하면 기존 자료에 합치고 별도 사례로 중복 생성하지 않음.
- 코퍼스 의견의 체크 ID와 현재 체크 ID가 일치하고 본건 후보에 복수 근거어가 있을 때만 운영 매칭 점수를 보강함. 자동판정 승인은 변경하지 않음.
- 자기 계약·동일 검토 ID·미해결 상충 수입파일·시스템 자동판정·위험수용 의견을 코퍼스 가산 자료에서 제외함. 새 의견 날짜를 과거 문서 날짜에 숨기지 않으며 계열 미상은 격리 시험 검색에서 제외함.
- 통합자료가 변경될 때 검색용 단어를 미리 계산함. 일반 입력 변경에는 전체 자료 재색인을 하지 않음.
- 평가 탭에 누적 판정 점검 버튼을 추가함. 기존 코퍼스의 근거 불충분 후 이상없음 기록과 보완 의견을 우선순위로 표시하며 제거된 체크는 제외함.
- 이 버튼은 원문 재채점·자동승인 기능이 아님. 전체 평가 절차 간소화와 원문 연결은 계속 구현해야 함.
- 운영 매칭 엔진 경유, 중복 연결, 자기참조, 출처·날짜·시험 격리, 간편 점검에 대한 시험을 추가함. 배포본은 아직 갱신하지 않음.

## 첫 구현 범위

- 판정 저장 시 결과·이유·주제·별첨 경로 태그를 로컬에서 생성함. 이유 없는 이상없음은 이유 미상으로 유지함.
- 코퍼스 신규 적재분에는 개별 판정 스냅샷, 계약검토 연결 ID, 태그와 수정 이력을 보존함.
- 현재 계약을 누적 저장하면 동일 계약의 변경 판정과 삭제 판정을 집계에 반영함. 같은 날짜의 상충 수입파일은 덮어쓰지 않고 보류함.
- 구 집계에 이미 포함된 계약은 새 판정·태그를 별도 보존함. 과거 계약별 기여분을 알 수 없으므로 기존 통계에서 임의로 빼거나 새 결과를 중복 가산하지 않음.
- 구 코퍼스 의견에도 검색용 패턴 태그를 생성할 수 있게 함. 원문이 연결된 시험사례로 표시하지 않음.
- 정확도·검토효율 현황에 판단태깅 수, 구 집계 중복 보존, 상충 파일 보류 안내를 추가함.
- 승인형 자동판정에서는 무관하고 다른 곳에 쓰이지 않는 독립 정의문만 전역 보류에서 제외함. 관련 정의·실제 예외·전역 제한·추출 불량은 유지함.

## 남은 구현

- 기존 코퍼스·계약검토·법률검토 자료의 실제 연결 및 판단태그를 활용하는 매핑 순위 개선.
- 본문·별첨·참조조항의 효력 범위를 연결하여 관련 없는 예외로 인한 보류를 더 줄이는 작업.
- 평가지원 단일 실행 화면, 계열 자동 분류, 원문 연결 사례의 실제 재채점과 비교.
- 성능 병목 측정, 작업 분리, 색인·캐시 적용. 이번 신규 적재는 기존 사건 전건을 재집계하지 않지만 기존 사건 수정은 아직 전체 활성 기록을 재집계함.
- 판정 태그 자체는 매 판정 저장 시 생성됨. 코퍼스 갱신은 기존 누적저장·검토완료 경로를 사용하며 매 클릭마다 무거운 코퍼스 재계산을 실행하지 않음.
- 구 집계와 겹치는 수정은 별도 기록에서 확인 가능하지만 기존 집계값 자체를 교정하지는 못함. 연결 복원 및 평가화면에서의 분리 처리가 남음.
- 배포용 빌드·브라우저 종단간 검증·폐쇄망 원문 실측. 현재 dist 파일은 갱신하지 않았으므로 이전 배포본임.

## 검증 원칙

- 첫 구현 검증 결과: JavaScript 전체 548개, Python 전체 103개 통과함. 앱 스크립트 구문검사도 통과함. 브라우저·폐쇄망 실측은 아직 수행하지 않음.
- 데이터 중복·삭제·수정·백업 병합, 조건부 의견, 위험 수용, 무관·관련 정의문에 대한 회귀시험을 추가함.
- 테스트용 합성자료만 소스에 추가함. 사용자 코퍼스나 원문을 코드·배포본에 내장하지 않음.
- 전체 계획 완료 또는 실제 자동판정률 향상으로 표현하지 않음.
