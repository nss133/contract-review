# 자동판정 안전성 1단계 — v1.54.0

2026-09-09. 계획의 P0 안전장치와 P1 내부 평가 기반을 구현한 버전이다. 실자료 정확도 향상이나 운영 승인 완료를 의미하지 않는다.

## 변경된 동작

- 자동 ‘이상없음’은 관찰 모드로 고정했다. 참고 체크의 매칭, 문장 요건, 회사관점 신호가 있어도 완료 처리하지 않는다. 태그·설정·과거 결론으로 이를 켤 수 없다.
- 일반 자동판정·표준약정·과거 승계·LLM 초안의 이상없음은 공통 저장/가져오기 관문에서 보류한다. 기존 기록은 원래 판정·사유·코멘트·일자·출처를 safety_hold.previous에 보존한다. 활성 판정은 빈값이며 완료·검토의견 건수 어느 쪽으로도 세지 않는다.
- 사람의 직접 판정(manual)·명시적 일괄 판정(bulk)은 보존한다. 출처가 없는 옛 기록(legacy)은 자동인지 사람이 작성했는지 단정할 수 없어 보존한다. 이 기록들은 별도 내부 감사 대상이며 독립 정답으로 자동 채택되지 않는다.
- 기존 자동기록을 사람이 재확인한 뒤 판정하면 이전 이력도 보존한다. 표준약정 사용 체크만으로 신규 판정은 만들지 않는다. 전년 이상없음 수용은 참고 이력만 남기며 본건을 다시 확인해야 한다.
- 본문·원계약·별첨의 단서/배제/우선 적용 표현을 표시한다. 넓은 문자열 신호이므로 다른 체크에 무관할 수도 있다. 의미 충돌의 완전한 검출, 예외 해소 또는 법적 부적정 판정이 아니다.
- 근거 조항을 수동 재지정하면 기존 조항에서 계산한 문장 요건·회사관점 신호를 지운다. 원래 위치로 복귀하면 원래 분석 신호를 복원한다.
- 보류된 기존 시스템 판정과 자동 후보는 전체 완료 계산에서도 재확인을 요구한다. 조항이 quiet로 바뀐 경우에도 현재 분석 체크에 포함되어 있으면 별도 확인 큐에 남긴다.

## 내부 평가 순서

1. 기존 영구 실행기에서 v1.54.0 업데이트를 적용한다. 설치 전 기존 검토의견과 브라우저 데이터의 내부 백업을 보관한다. 예전 실행기 위치는 바꾸지 않는다.
2. 계약서·별첨·원계약을 넣고 유형·역할·적용범위를 확인해 분석한다. 관리모드의 ‘골드셋 채점’ 탭에서 ‘자동판정 안전성 · 폐쇄망 내부 평가’를 연다.
3. 계약 계열 ID를 입력한다. 같은 원계약·갱신·유사 서식은 같은 ID를 사용한다. 현재 계약 평가 스냅샷을 고정한다.
4. ‘블라인드 정답 양식’과 ‘관찰 기록’을 각각 내부 승인 폴더에 저장한다. 두 파일에는 본문·메타데이터가 들어간다. 반출하지 않는다. 정답 검수자에게 관찰 기록은 전달하지 않는다.
5. 정답 JSON의 reviewer, source_reviewed, independent를 검수 사실에 맞게 채운다. 각 labels 항목의 truth는 safe(수정·추가 확인 불필요), issue(문제 있음), unknown(판단불가), not_applicable(비적용) 중 하나로 작성한다. 미검수는 빈 문자열로 둔다. 확정한 라벨에는 note(사유), evidence(원본 문서·조항 위치)를 반드시 적는다. direct_clause_indices는 본문의 직접 관련 조항 번호 배열이며 양식의 clauses.index를 따른다. 근거가 없으면 빈 배열이다.
6. 관찰 기록과 정답을 화면에 각각 불러와 채점한다. 스냅샷·계약 지문·계열·앱/정책 버전이 다르거나 라벨 중복·잘못된 위치·검수확인이 없으면 채점을 보류한다. 기존 회귀 골드셋의 ‘관측 결과로 기대값 갱신’은 이 정답을 변경하지 않는다.

정답 파일 작성은 현재 JSON 방식이다. 원본·사람·예측의 분리는 절차와 필드 검증이며, 독립 검수의 실제 수행을 기술적으로 증명하지는 않는다. 운영 승인 전에는 독립 검수자와 재검수 절차가 필요하다.

## 표시되는 지표와 한계

- 현재 정책: 실제 자동확정 0건. 이는 정확도 100%가 아니라 자동처리 표본 없음이다.
- 이전 정책 가상 후보: 기존 일반 자동정책과 현재 사용 선언된 표준약정의 후보를 고정한 비교군. 전년 수용 버튼 등 사람 행동의 전체 로그를 재현하는 비교군은 아니다.
- 후보 중 문제 있음·판단불가·미검수를 별도로 표시한다. 미검수 포함 전체 후보 대비 확인된 오류 비율은 실제 오류율의 확정 추정치가 아니다.
- 전체 240개 체크를 포함하므로 비활성 모듈·다른 유형·quiet도 검수할 수 있다. 문제 정답인데 표시되지 않은 항목을 별도로 센다. 검수하지 않은 항목은 안전 정답으로 보지 않는다.
- Top1/Top3는 사람이 직접 근거 조항을 지정한 체크가 분모다. 복수 조항 요건의 완전한 충족이나 법적 충분성의 지표가 아니다.
- 한 파일 쌍의 단일 계약 진단이다. 모듈의 0오류 상한 계산은 독립 표본 가정의 참고용이며 UI에서 안전 보증 수치로 표시하지 않는다. 계약 내 체크들은 독립 표본이 아니다.
- 모든 원본·태그·통계·식별자·관찰/정답 파일은 내부 전용이다. 앱의 로컬 저장/다운로드는 망 반출 허가가 아니다. 선택형 로컬 AI의 기존 설정은 바꾸지 않았으며 이번 평가에는 외부 서비스가 필요하지 않다.

## 다음 단계 — 아직 미구현/미검증

계열·서식·시간을 분리한 다계약 고정 시험셋, 검색 이력 누수 차단, 2인 독립 검수/이견 조정, 의무 주체·객체·조건의 구조적 충족 검사, 실제 의미 충돌 해소, 규칙별 승인·만료·롤백, 좁은 자동허용 목록은 후속 단계다. 현재 내부 평가 결과만으로 자동허용을 켜는 기능은 제공하지 않는다.

폐쇄망 실자료를 반출하지 않았고 직접 평가하지 않았다. 외부에서는 합성자료와 기존 회귀시험으로 기능 동작만 검증한다.

## 개발 검증

- Node 단위·회귀 465건 통과, Python 빌드·골드셋 103건 통과.
- 브라우저 합성 회귀: 기존 자동기록 이관·사람 판정 보존·표준약정/승계 보류·전체 완료 게이트·단서 안내·재지정·240개 체크의 분리 파일 저장·내부 채점·스냅샷 불일치 차단 통과. 해당 시험의 외부 HTTP 요청 0건.
- 기존 업무·규제 해당성/체크 묶음 브라우저 회귀와 영구 실행기의 업데이트·태깅/이력 보존 흐름 확인.
- 이 결과는 구현 회귀 근거이며 실제 계약 판단의 정확도 수치가 아니다.
