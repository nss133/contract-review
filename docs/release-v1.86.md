# v1.86.0 — 조·항·호·목 범위 참조 비교

## 이번에 완료한 개발

‘제1항부터 제3항까지’, ‘제1호 내지 제3호’처럼 범위를 지정한 약정을 비교하도록 보강했습니다. 시작과 끝 번호만 확인하지 않고 중간 번호의 원문까지 연결합니다. 기존의 범위 참조 일괄 보류를 줄이고, 등록 표준·확인된 사용자 판단을 같은 범위에 재사용할 수 있게 했습니다.

- 같은 구역의 연속된 조, 같은 조의 항, 같은 목록의 호, 지정한 호 안의 목을 지원합니다. ‘부터…까지’, ‘내지’, 물결표 세 종류(~·∼·～)를 읽습니다. 항·호·목은 v1.85에서 지원한 명시 번호와 목록 구조를 전제로 합니다.
- 범위 안의 모든 번호가 유일하고 원문 순서대로 존재하는지 검사합니다. 본문 없는 번호, 누락·중복·역순, 서로 다른 조·항·호를 넘나드는 혼합 경로, 끊어진 범위를 임의로 보완하지 않습니다. 한 범위의 확장은 최대 100개 번호로 제한하며 비정상적으로 큰 숫자로 반복 처리가 멈추지 않도록 검사합니다.
- 같은 참조 대상과 범위가 확인된 경우에만 ‘부터…까지’와 ‘내지’ 등의 표기 차이를 동등하게 비교합니다. 범위의 축소·확대, 중간 조항의 기간·주체·조건 변경은 별도로 구분합니다. 외부 법령의 번호를 본 계약의 같은 번호와 연결하지 않습니다.
- 다른 조에서 범위 전체를 배제하거나 제한한 문장도 읽습니다. 범위 중간의 조 번호가 누락·중복되거나 가지번호가 있어 해석을 확정할 수 없더라도, 그 제한 문구를 버려 기존 이상없음이 남지 않도록 보강했습니다.
- 근거에는 실제 참조 문구와 연결된 중간 항목의 원문을 표시합니다. 내부 비교용 표준화 문구를 원문인 것처럼 표시하지 않습니다.

범위 참조가 있다는 사실만으로 적정성을 판정하지 않습니다. 등록 표준이나 원문·적용 맥락으로 확인된 사용자 판단이 있어야 그 경로로 자동완료할 수 있습니다. 직접 판정 규칙은 제한·미해석 문장을 계속 검사합니다. 태그 단독 승인, 실제 의무 이행 확인, 외부 AI 호출은 추가하지 않았습니다.

## 저장자료·화면

기존 자동등록 표준은 연결 규칙 14로 재승인 없이 갱신합니다. 이전 규칙 13에서 범위 참조 때문에 연결되지 않았던 자료도 다시 검사합니다. 수동 설정과 사용 중지 상태는 유지합니다.

자동 이상없음은 기존 조항별 검토의 ② 확인 완료에 표시합니다. 중간 조항·참조 범위·원문이 바뀌거나 사용자의 최신 수정의견이 확인되면 자동판정을 다시 검사합니다. 사용자가 직접 남긴 판정은 덮어쓰지 않습니다.

## 검증

Node 1,016개·Python 106개, 총 1,122개 회귀시험과 배포 HTML의 브라우저 16개 흐름을 통과했습니다. 신규 단위시험 26개에 조·항·호·목별 표기 변형과 중간 번호·조건·누락·중복·역방향 제한·외부 참조·과거 판단·등록 표준 비교를 포함했습니다.

배포 화면에서 네 단계 범위의 사용자 판단 재사용, 원문 근거와 중간 항목 표시, ②열 이동, 중간 내용 변경·범위 축소·역순 편집 시 철회를 확인했습니다. 범위형 표준의 자동등록, 누락 시 철회, 최신 정정과 수동판정 보존, 등록 규칙 13→14 갱신도 확인했습니다. 기존 중첩 목록·표준·코퍼스·완료·실제 PDF 등록 흐름을 함께 검사했으며 시험한 앱 흐름에 런타임 오류와 외부 통신은 없었습니다.

직접 판정 64개·관련 조항 이력 재사용 66개의 질문 범위는 유지합니다. 기존 보안관리약정서 3종에 무관한 조항을 더한 표준 비교는 3·6·6개, 공개 자료 5종의 직접 충족은 0개로 유지됐습니다. 이번 시험은 지원하는 참조 표현을 확장한 개발 검증이며, 실제 폐쇄망 자동판정률·오판율의 변화는 아직 실측하지 않았습니다.

## 적용과 남은 개발

기존 실행기의 ‘버전 설치·업데이트’에서 contract-review-v1.86.0.crupdate를 선택한 뒤 계약을 재분석하십시오. 실행기의 위치·이름과 브라우저 프로필을 유지하고 내부 백업을 보관하면 됩니다. 원문 반출이나 별도 자료 승인은 필요하지 않습니다. 내부 약정서 원문과 사용자 코퍼스는 배포본에 내장하지 않았습니다.

이번 배포의 범위 참조 개발은 완료했습니다. 표 셀에 나뉜 주체·의무 연결과 추가 정형 표현 확대는 별도 개발 항목으로 남아 있습니다. 사라진 번호 복원, 가지번호를 포함한 조 범위, 서로 다른 부모를 가로지르는 범위, 세 단계 이상 목록, 임의 의역과 복잡한 조건의 법적 우선순위 판단은 이번 지원 범위가 아닙니다. HWP·HWPX·DOCX·PDF에서 추출한 공통 텍스트에 적용하며 모든 변환 오류를 복원하지는 않습니다. 개발 시험 통과를 실업무 오판율 0으로 해석하지 않습니다.
