# v1.88.0 사용안내 — 약정 확인 중심 자동판정

## 업데이트 후 할 일

1. 기존에 쓰던 실행기를 같은 위치에서 열고, 이번 ZIP의 contract-review-v1.88.0.crupdate를 적용한다. 새 실행 위치로 옮기면 브라우저 저장소가 달라 보일 수 있으므로 기존 실행 위치를 유지한다.
2. 기존 계약을 불러와 재분석한다. 자동 이상없음은 조항별 검토의 기존 삼단 화면에서 ② 확인 완료에 표시된다. 다시 수기로 이상없음을 누를 필요가 없다.
3. 표준계약서·보안관리약정서는 등록 표준서식에 파일을 넣으면 자동 처리된다. 이미 등록된 자동 연결 자료는 새 기준으로 갱신된다. 자료별 승인·평가후보 선택·계약 계열 ID 입력은 필요하지 않다.
4. 본건에 적용되는 별첨은 부속 서류로 추가한다. 본건이 등록 표준의 이름·판본을 명확히 편입한 경우에는 그 등록 원문도 연결한다. 단순히 자료실에 있다는 이유로 모든 계약에 적용하지 않는다.

기존 판정·태그·코퍼스·표준 원문은 지우지 않는다. 업데이트 전에 기존 앱의 백업 기능으로 폐쇄망 내부에 백업을 보관하면 복구에 도움이 된다. .crhistory·태그 DB를 외부로 반출할 필요는 없다. 사용자가 명시적으로 꺼 둔 자동판정 설정은 보존되므로, 자동판정 현황에 ‘중지’가 표시되면 그 설정만 확인한다.

## 이번에 달라지는 점

- 관할: 특정 법원뿐 아니라 ‘갑 본사 소재지 관할 법원’, 중재 방식 등도 인정한다. 관할 제목만 있는 문구는 통과하지 않는다.
- VAT·대금·기간: 짧은 부가세 별도/포함, 표의 값, 콜론 없는 기간, 발주 건별 단가 정산 등을 읽는다. 월말 정산이나 특정 지급일·30일 시정기간을 보편 필수로 요구하지 않는다.
- 손해배상·해지: 약정 존재와 구체적인 편중 위험을 구별한다. 책임을 정하는 면책 문구 자체로 존재 확인을 막지 않고, 상대방의 고의·중과실 전면 면책 등 정의된 위험만 해당 항목에서 표시한다.
- 점검·교육·보안약정: 계약상 권한·협조·보호 내용으로 판단한다. 실제 점검·교육·신고를 했는지는 확인하지 않는다. 표준약정 전체 일치나 별도 승인 없이 본건의 동등 취지를 사용한다.
- 태그·과거 의견: 현재 표현과 매핑 후보를 보강한다. 과거 이상없음의 수나 검토의견이 있다는 사실만으로 현재 결론을 복사하거나 보류하지 않는다. 내용 태그와 결과 태그를 분리하여 새 수기 판정에도 저장한다.
- 상태: 자동 완료·화면·리포트·검토 마치기가 같은 판정 값을 사용한다. 무관한 DB 추가·화면 전환으로 수기 확인을 초기화하지 않으며, 실제 관련 내용 변경과 동시 수기 수정 충돌만 구분한다.

‘다만’이라는 단어, 약정과 무관한 추출 공백, 일반적인 당사자 호칭 차이만으로 일괄 보류하지 않는다. 실제 필요한 근거가 미정·공란이거나 같은 약정을 배제·충돌시키는 내용이 있으면 그 이유와 원문 위치를 표시한다.

## 체크리스트 범위

206개 원 ID를 보존하여 전수 정리했다. 활성 184개, 비활성 22개이며, 비활성은 제품 범위 제외 9개·실제 이행 제외 9개·내용 통합 4개이다. 활성 중 약정 확인 62개, 명확성 판단 52개, 적정성·유불리 판단 70개이다. 숫자는 계약 한 건의 표시 항목 수나 자동판정률이 아니다.

CORE-13은 CORE-10으로, PRIV-08·NDA-15·SP-DEL-06은 CNS-DAMAGE로 통합한다. 구 항목의 수기 기록은 남기되 하나의 옛 이상없음을 새로운 통합 질문 전체의 결론으로 복사하지 않는다. 제외 ID는 새 매핑·미결·완료 차단에 다시 나타나지 않는다. 상세 내용은 함께 든 206개 기준표를 참조한다.

## 확인 범위와 한계

개발 검증은 질문별 양성·음성, 실제 보안약정 3종, 표·목록·참조·별첨, 상태 유지와 실제 4형식 입력 흐름을 대상으로 한다. 최종 실행 수치와 배포 지문은 검증기록에 별도로 남긴다.

29건 코퍼스에는 판정·코멘트 집계가 있으나 계약 원문 묶음은 없다. 따라서 이를 29건 실계약 재실행이나 폐쇄망 자동판정률로 보고하지 않는다. 합성·표준 시험 통과는 모든 실계약의 오판이 없다는 보장이 아니다.

HWP·HWPX·DOCX·텍스트 PDF를 지원한다. 이미지뿐인 스캔이나 암호·손상 파일은 읽히지 않은 부분을 임의로 복원하지 않는다. 필요한 원문을 못 읽으면 텍스트 미확보로 안내하며, 다른 읽힌 조항까지 일괄 실패시키지 않는다. LLM·외부 API·온라인 연결은 필요하지 않다.

ZIP에는 사용자 코퍼스·보안약정 원문을 넣지 않는다. 과거 작업대 승인 절차 안내는 이전 버전 기록으로만 보관하며 이번 사용 절차가 아니다.
