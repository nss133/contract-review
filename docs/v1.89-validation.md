# v1.89.0 검증기록 — 근거 표시·검색·저장 성능

검증일: 2026-09-18. 사용자가 승인한 v1.88 브라우저 멈춤 수정의 로컬 구현·검증 기록이다. 폐쇄망 실제 계약이나 사용자 브라우저 저장소를 수정하여 시험하지 않았다.

## 변경 범위

- 카드당 검증된 대표 근거의 원문 보기 버튼은 최대 하나. 전체 원문은 기본 카드와 자동 메모에 나열하지 않으며, 내부 proof의 원문·좌표와 수기 메모는 보존한다.
- 과거 의견 검색은 다중 구절 색인으로 현재 조항을 찾는다. 후보 최대 200개, 최장 일치 표현, 상위 5개와 안정 정렬은 유지한다.
- 매핑은 분석 한 번 안에서 조항·체크별 벡터를 선계산한다. 점수·정렬·게이트 의미는 유지한다.
- 등록 표준은 원문 및 질문별 결과를 재사용한다. 전체 별칭 순회는 주제별 인덱스로 바꾸고, 실제 UI에서 빠져 있던 정본 별칭 사전도 연결한다.
- 긴 문서 구조 분석의 앞선 줄 전체 복사를 없앴다. 원본의 중첩 변경을 감지한 후 별도의 불변 문서 스냅샷을 만들며 사용자 원본은 동결하지 않는다.
- 수기 메모는 입력 즉시 현재 판정에 반영하고 250ms 단위로 저장을 합친다. change·blur·pagehide·beforeunload·페이지 숨김 및 계약 전환 전에 남은 저장을 처리한다. 새 수기 의존값은 v3만 쓰되 구 v1·v2 기록은 계속 읽는다.
- 평가자료 저장 알림은 원문이 아닌 변경 ID만 전달한다. 시작·전체 복원 때는 전체 자료를 읽고 단건 변경은 get으로 처리한다. 본건 메모 변경만으로 현재 화면을 다시 만들지 않되, 표준 표현의 출처 패킷이면 즉시 재검사한다.

판정 기준을 넓게 완화하거나 자동판정을 줄이는 수정은 아니다. 명시 별칭의 부정을 읽을 때 기존에 놓친 ‘하지 않으며’ 어미를 국소적으로 보완했다. 단위 없는 긴 가격 문자열의 정규식도 동등한 인식을 유지하도록 정리했다. 체크 ID·판단 수준·자동판정 중지 설정은 바꾸지 않았다.

## 기능·안전 검증

기존 회귀시험과 새로운 근거 표시·동시 수기 저장·단건 자료 갱신·캐시 변조 및 무효화 시험을 수행했다. 다음을 구분하여 검사한다.

최종 전체 Node 시험은 1,527/1,527 통과, Python 시험은 107/107 통과했다. 실패·skip·todo는 0개다. Node 실행에는 CR_REQUIRED_PRIVATE=1을 적용하여 기존 보안약정 원문 fixture도 빠지지 않게 했다. 별도 고정 합성 61사례는 양성 30/30, 음성 오통과 0/31이며, 7설정의 소스 기여 비교도 기대값과 일치했다. 이 결과는 실제 사용자 계약의 오판율이 아니다.

- 근거 1,000개에서도 카드 버튼 1개, 원문 미삽입, 내부 근거 1,000개 유지. 좌표가 무효면 버튼 0개.
- 기존 수기 내용·동시 편집 의견을 보존하며 저장 직전 마지막 글자를 flush한다.
- 원문·표준·binding·추출블록·별칭·판정 결과 변경 후 이전 티켓을 재사용하지 않는다. 화면용 근거 편집으로 검사 캐시가 오염되지 않는다.
- 같은 자료의 반복 계산은 재사용하되 같은 객체 내부의 실제 변경도 재검사한다. 자료 원본은 그대로 두고 스냅샷만 동결한다.
- 첫 100건 로드 뒤 한 건을 변경해도 전체 getAll을 호출하지 않는다. 조회 중 발생한 새 변경과 삭제를 놓치지 않는다.
- 직접 함수의 자료별 기여 비교는 기존 고정 합성 10사례·7설정 및 좌표·매핑 기대값을 유지한다. 이것을 폐쇄망 실제 자동판정률로 환산하지 않는다.

## 실제 앱 성능·저장 수용시험

전용 임시 Chrome 프로필과 독립 컨텍스트를 사용한다. 사용자 브라우저 프로필·실제 계약·폐쇄망 저장소는 사용하지 않으며 외부 HTTP 요청은 0건이다.

최종 HTML SHA-256: 26ae13ef4e9ddf6c0fd650b2f27cf5dc5475dc661b49d1e816ff9c4c6923c962.

성능 수용시험 7조건에서 다음을 확인했다.

1. 실제 UI에서 암호화 별칭 없는 문구는 미판정, 명시 별칭을 넣은 긍정 문구는 자동 완료·②열, 같은 별칭의 부정 문구는 미통과.
2. 71,147자·작성 1,400조항의 일반 텍스트와 71,148자·2,803추출블록 구조형에서 카드당 근거 최대 하나, 자동 메모 간결화, 내부 근거 유지, 원문 팝업 좌표 일치, 반복 재분석 완료 유지.
3. 구기준 연결 후보 표준 40개 뒤의 정상 표준을 찾아 연결하고, 정상 표준을 비활성화하면 낡은 연결을 취소.
4. 과거 내부 평가자료 100건과 자동저장 ON에서 실제 input 이벤트·마지막 입력 직후 재로드·재분석을 거쳐 수기 메모 및 다른 자동판정을 유지.

상세 원시 결과는 v1.89-performance-acceptance.json에 있다. 단건 수기 입력 시간에는 나중에 실행되는 IndexedDB 저장 완료 시간은 포함되지 않는다.

## 동일 조건 성능 비교

v1.88 배포 업데이트에 들어 있는 HTML과 위 지문의 v1.89 HTML을 동일 장비의 격리 컨텍스트에서 비교했다. 조건마다 초기 1회, 워밍업 1회 뒤 재분석·화면 재표시 각 10회를 측정했다. 모든 조건은 질문 28개·자동 완료 13개로 동일했고 내부 근거 수·좌표·조항 배치도 일치했다.

| 조건 | v1.88 재분석 P50 / P95 | v1.89 재분석 P50 / P95 |
|---|---:|---:|
| 일반 텍스트 71,147자 | 5,228.7 / 6,181.8ms | 429.5 / 841.1ms |
| 추출블록 2,803개 포함 | 5,286.8 / 6,508.3ms | 444.1 / 707.5ms |
| 구기준 표준 40개 + 정상 표준 1개 | 5,280.8 / 6,194.2ms | 420.2 / 463.9ms |

일반 텍스트 최초 분석은 7,188.8→776.7ms, 구조형 최초 분석은 7,378.0→854.2ms였다. 각 1회값이므로 평균·분위수로 부르지 않는다. 기존 카드당 근거 버튼 최대 200개는 최대 1개가 됐고 자동 메모의 원문 반복을 제거했다. 순수 화면 재표시를 포함한 나머지 표본은 v1.89-runtime-benchmark.json에 보존한다.

별도 내부 평가자료 100건·자동저장 ON 시험에서 실제 입력 이벤트 27회의 P50/P95는 0.7/1.0ms였다. 별도 1회 관측에서 자료 로드 436ms, 일반 판정 저장 19.3ms, 내부 평가자료 저장 695.3ms였다. 입력 이벤트 시간과 저장 완료 시간은 서로 다른 측정이며 합산한 지연으로 해석하지 않는다. 실제 재로드 직전 마지막 입력 및 재분석 후 수기 상태가 유지됐다.

## 파일 입력·상태·실행기 회귀

최종 HTML에서 별도의 전용 컨텍스트로 다음 시험을 통과했다. 성능 비교 측정이 끝난 후 실행하여 비교 표본과 섞지 않았다.

- 실제 합성 HWP 5·HWPX·DOCX·텍스트 PDF 바이트 → 추출 → 핵심 6개 자동 완료 → 기존 ②열 → 재분석 → 검토 마치기·수기 보존. 추출 함수를 가짜 결과로 교체하지 않았다.
- 일반 면책의 약정 존재는 확인하고, 상대방의 고의·중과실 전면 면책은 별도로 차단. 재로드·본문 편집에 따른 낡은 자동 완료 회수, 명시적 중지 설정 유지·무승인 재개, 표준 등록·재로드 연결을 확인.
- 별도 임시 프로필의 실행기에서 합성 태그 XLSX 1건·검토이력 2건을 반입한 후 재실행과 모의 다음 업데이트를 거쳐 각각 1건·2건이 유지됨. 테스트용 다음 버전 표시는 v1.89.0-next-test이며 실제 후속 배포가 아님.

네 형식의 입력 시험은 작은 합성 파일이다. 앞 절의 2,803블록 시험은 추출 후 구조형 자료를 넣은 별도 스트레스 시험이며 두 시험을 ‘긴 실제 파일 4종의 변환 속도 측정’으로 합쳐 주장하지 않는다. 라이프사이클 시험의 표준 업로드 일부는 합성 추출 fixture를 사용하므로 이 역시 실제 4형식 추출 성과와 구분한다.

## 측정 해석의 한계

긴 계약은 서로 다른 14개 합성 약정을 100회 반복하여 확장했다. 실제 계약의 다양한 문장 분포나 실제 대형 태그 DB를 대표하지 않는다. 구조형은 추출 후 블록 자료를 주입한 성능시험이고, 실제 파일 바이트 입력 시험과 구분한다. 표준 후보와 내부 평가자료도 합성이다.

브라우저 성능 비교의 최초 분석은 조건별 1회, 재분석·렌더는 워밍업 후 10회로 구분한다. P50/P95는 nearest-rank이며, 파일 변환·앱 실행기 로딩·GPU 페인트·비동기 저장 완료 전체를 포함하는 수치가 아니다. 중단되거나 다른 시험과 겹친 비교 실행은 최종 표본에서 제외했다.

기존 판정 범위와 읽히지 않는 원문에 대한 한계는 유지한다. 이 기록은 모든 실계약의 오판 0, 모든 PC의 멈춤 해소 또는 실제 자동판정률 향상을 인증하는 자료가 아니다. ZIP에는 실제 사용자 코퍼스·표준 원문·이력팩을 넣지 않는다.
